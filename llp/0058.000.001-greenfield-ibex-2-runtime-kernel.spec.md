## Summary

Ibex 2 uses a new runtime path around pinned, unmodified upstream Hermes and a Rust-owned kernel, not an in-place deletion of legacy mechanisms.

"Greenfield" means a new root, bootstrap, loader, module ABI, records, driver, and adapter while reusing compliant audited leaves, transports, provenance, and fixtures. The patched runtime stays separate and authoritative where required, never a kernel library or fallback.

## 1. Relationship to the 0058 family

This Spec owns **topology, ownership, reuse, sequencing, receipts, and artifact cutover**. LLP 0058.000.000 governs the security protocol; §3.1 maps its driver and §6 preserves its bootstrap.

It supersedes only the pre-2026-08-27 **incremental-in-place strategy** in LLP 0057 §5.1, LLP 0058.000 §6 M2-M6, and LLP 0058.000.000 §12. Those documents otherwise remain current.

LLP 0021 staging/digests/arming/fail-closed mismatch and LLP 0039 selection/identity/no-downgrade remain governing. Greenfield does **not** inherit LLP 0021's Ibex 1 catalog or three Hermes structural cells. An accepted amendment must generate cells from LLP 0058.000 §8.6 (`Absent` / `Refuses` / `Joins`); until then, G6 fails. No parallel claim plane exists.

## 2. Exact meaning of greenfield

A greenfield Ibex 2 runtime instance has all of these properties:

1. Its build selects a new, explicit source/dependency closure, not the legacy runtime with patches or features disabled.
2. Its Hermes input is an exact upstream pin bound by a `HermesInputReceipt` (§5).
3. Its first project-code entry is a receipt-bound `FactoryV1` artifact; it never evaluates an artifact that expects authority on the real global.
4. Its Rust kernel mints every context, binding, resource, callback, and completion record before an authority-bearing JavaScript value exists.
5. Its engine adapter uses public Hermes embedding interfaces only and owns no grant, principal, or receipt policy.
6. Its platform services are reached only after the typed Rust operation and each required Requested/Discovery/Commit/Repeat authorization.
7. Its task loop is the single driver of LLP 0058.000.000 §8, run by the kernel's owner-thread coordinator (§3.1).
8. Missing APIs are absent or refuse; they never call a legacy engine global, generic bridge, process-ambient service, or compatibility implementation.

Greenfield and patched are separate artifacts (§5); a product loads one before runtime creation, and no execution, graph, callback, handle, or completion crosses families.

## 3. Normative component topology

Physical paths may change; the dependency graph and ownership below are normative.

```text
 module sources --> FactoryV1/HBC builder (build time) --> artifact + ModuleReceipt
 product shell --> greenfield composition root (sole strong owner)
                     +-- Rust runtime kernel: owner-thread coordinator (§8 driver),
                     |     policy projection, operation/resource machines, stdlib semantics
                     +-- runtime loader (receipt check, mint_context)
                     +-- public-Hermes adapter (engine hooks)
                     +-- platform services (transport)
 loader/adapter/services --calls--> kernel operations (LLP 0058.000.000 §4)
 kernel coordinator --calls--> JS-free hooks implemented by adapter/services
```

### 3.1 Rust runtime kernel

The kernel owns LLP 0058.000.000 records/transitions **and the owner-thread coordinator** implementing its driver and teardown. It contains no JSI, engine/JS value, root, C++ runtime pointer, or transport; its boundary is typed data, private keys, leases, and service traits.

Only the kernel may authorize an effect, mutate policy generation, mint or derive authority, commit a resource stage, admit or commit a host task, or begin teardown. Loader, adapter, and services reach it through the operation contract of LLP 0058.000.000 §4; the coordinator reaches the adapter through the JS-free hooks `checkpoint`, `invoke`, `release`, and `destroy_engine`, and each service through `dispose`. Neither adapter nor services run a pump or lifecycle state machine.

**Ownership.** The root solely owns kernel, loader, adapter, and services; reverse links are weak, borrowed, or generation-keyed. Hook registration is one-time and sealed; partial bootstrap destroys built state in barrier order. No kernel table/queue/teardown guard spans a reentrant hook or service call.

**Delegated driver.** LLP 0058.000.000 §8 step 3 runs here as: the coordinator calls `checkpoint`; the kernel reserves the head host task and revalidates its records; the adapter synchronously revalidates only that task's engine-slot state; the kernel, the sole source-transition commit actor, commits or rolls back; then the coordinator calls `invoke`. Each reservation returns exactly one synchronous owner-thread outcome: `RollbackUnstarted` (the task keeps its FIFO position), `CommittedStarted`, or `TerminalDisposed`. An `invoke` failure after commit is terminal, never rollback. The kernel holds the only host-task FIFO; the adapter's keyed engine-root slot table carries no scheduling, policy, or callback-lifecycle semantics.

Records reference roots/transports only through opaque owner slots; slots change only through reservation outcomes or barrier acknowledgements. Nothing commits after `Closing` or recycles before release acknowledgement.

**Teardown barrier.** In fixed order: the coordinator enters `Closing`; each service disposes or detaches every slot and acknowledges; the adapter releases every engine root and acknowledges; the adapter destroys Hermes and acknowledges; only then does the kernel close and recycle records. Service disposal, adapter root release, and adapter engine destruction are distinct synchronous owner-thread acknowledgements, each proving its owner holds no engine or transport reference for the generation. A missing or failed acknowledgement prevents every later step and all record recycling, quarantines the generation, and is fatal to the containing runtime host; a late `CompletionLease` result for a quarantined or closed generation drops through a generation tombstone without running JavaScript. Silent skip is forbidden.

Mock hooks/services must run the suite. A kernel leaf crate may use only §4.1 stdlib algorithms, never its boundary/dispatcher, C ABI, or adapter (§4.3, §5).

### 3.2 Public-Hermes adapter

The adapter owns only public-Hermes runtime creation/destruction; namespace materialization and `FactoryV1` invocation when directed by the loader with a kernel-issued namespace token; typed conversion; private-token closures/host objects; keyed root slots released on the §3.1 barrier; refusal materialization; and the coordinator-directed hooks. It never receives or invents a `PrincipalId`.

It may be a small Ibex-owned C++ layer outside the Hermes tree. It must not include Hermes private VM headers, link patched exports, inspect frames/jobs for identity, manufacture a principal, verify a receipt, own a task queue or callback map, or call legacy `ex_hermes_*` paths that install the old runtime surface.

### 3.3 Module builder and runtime loader

The build-time builder authenticates the graph, lowers every supported module shape to the exact `FactoryV1` ABI, emits HBC where selected, and produces the `ModuleReceipt` over the closed digest domain of §5.

The runtime loader is a separately root-owned, kernel-adjacent component, never part of the adapter. Only it verifies the `ModuleReceipt`, refusing at startup unless its `hermesc` digest/invocation, lowering authority, HBC ABI, and bound engine digest equal the authenticated live `HermesInputReceipt`; only it calls kernel `mint_context`; and only it asks the adapter to invoke a prepared `FactoryV1` with a kernel-issued namespace token. It never transpiles at runtime, rewrites free global references, retrofits old HBC, discovers modules ambiently, or falls back to a root context. Unsupported source, CommonJS, ESM, dynamic-source, or bytecode shapes refuse before project code.

### 3.4 Platform services

Platform services own transport, never policy. Typed traits accept no engine value or authority-claiming scalar, return verified facts for the next Rust stage, never turn `Staged` into allow, hold keyed slots disposed on §3.1's barrier, and deliver via `CompletionLease`, never runtime/callback pointers.

### 3.5 Product composition root

One small composition root constructs and solely owns kernel, loader, adapter, and services (§3.1) and selects the receipt chain, posture, authenticated policy/graph, and platform services. Family choice is an artifact choice (§5); a secure greenfield artifact contains no legacy family to select. Selection precedes runtime allocation and is disclosed. Before offering a secure greenfield selection, the root authenticates the `GreenfieldFinalArtifactReceipt`, `GraduationManifest`, and tier definition (§5, §10) against product-pinned identities.

## 4. Reuse policy

Reuse is per component.

### 4.1 Reuse after an engine-independence audit

Pure Rust algorithm/state-machine logic is reusable only when tests prove no engine/identity/global dependency, no effect outside the kernel, bounded inline work, and new error/resource contracts. An audit may extract an algorithm while rejecting its surrounding authority API.

### 4.2 Reuse behind a new typed service trait

Reuse typed CapSec semantics, authenticated service stages, transports, provenance, and fixtures behind new typed traits. Process-global Host/context/VFS lookup entry points are excluded.

### 4.3 Reference-only legacy code

The following are behavioral evidence or deletion targets, never dependencies of the new runtime: the Hermes patch stack and every patched identity/provenance export; frame/principal-stack collectors, scheduler-principal propagation, thread-local current-principal state, and principal-zero/root fallback; the legacy Hermes runtime/bootstrap surface, its capability-bearing real-global installers, construction spellings such as `__ibex2ReadFile`, and any JavaScript-callable operation-ID dispatcher; `crates/stdlib::boundary`, the `ibex2_stdlib_*` C ABI, `stdlib_adapter`, and JavaScript-supplied scalar `CallContext` or raw `HostHandle` authority; the process-global `Host`, its ABI context maps, and its VFS generation registry as runtime-selected state; and legacy transpilation, compartment-global emulation, old HBC that looks up authority on `globalThis`, and any compatibility bridge that executes an effect without joining the new kernel.

Differential tests may run the old runtime separately, never as an in-runtime oracle or authorization source.

## 5. Build, artifact, and dependency isolation

**Artifact boundary.** Greenfield and patched runtimes are separate final artifacts; a final artifact is the exact bytes a product loads to obtain a runtime family, an executable or a dynamically loaded library with its transitive link closure. A secure greenfield artifact links exactly the greenfield source closure; the patched family ships as its own artifact and receipt, and a product loads one before runtime creation. Any process, executable, or common loader capable of loading both families is a dual-family boundary and needs a separate accepted amendment defining a family-tagged opaque runtime handle, authenticated dispatch, and a per-constructor reachability inventory; sublibrary scans never authorize it.

**Receipt chain.** Four artifacts have distinct schemas/producers and no self-hash; the final receipt cross-binds the preceding set.

1. `HermesInputReceipt` (`ibex/hermes-upstream-pinned-receipt/1`; G0, with an independent validator) binds the upstream tree, canonical empty patch manifest, exact `hermesc` bytes/flags, lowering authority, HBC ABI, target/variant, and Hermes runtime/link artifacts. Patched/Maven classes cannot be relabeled; Android also requires a source-built empty-patch artifact.
2. `ModuleReceipt` (`ibex/greenfield-module-receipt/1`; per graph, from the §3.3 builder; schema delivered at G2) has a canonical, closed digest domain: authenticated source bodies and graph edges/IDs; factory wrapper/version; binding profile and stdlib surface; builder/lowering executable closure with its configuration, plugins, and flags; exact `hermesc` bytes/invocation; factory/HBC output bytes and ABI; and the `HermesInputReceipt` digest. Extra or missing fields fail.
3. `GraduationManifest` (`ibex/greenfield-graduation-manifest/1`; §10) binds the tier-definition digest, its evidence inputs, and the final source/link closure digests.
4. `GreenfieldFinalArtifactReceipt` (`ibex/greenfield-final-artifact-receipt/1`; an external sidecar written by the post-link scanner) binds the exact loaded artifact bytes, actual linker/object/entry-root closure, every negative-scan input/result, the `HermesInputReceipt`, admitted `ModuleReceipt` digest set, tier-definition digest, and `GraduationManifest` digest. Its closure digests MUST equal the manifest's; neither artifact contains its own digest.

Product configuration pins final-receipt and tier identities for pre-allocation comparison. Before graduation the chain is oracle/experimental and cannot run untrusted code unless disclosed and trip-wired per LLP 0039 and LLP 0058.000 M1.

The build must provide these negative guarantees; path names are denylist prefixes, not a mandated layout (§11):

1. The greenfield native source list contains only the new adapter and audited platform leaves; no legacy Hermes runtime/bootstrap translation unit is compiled.
2. The Hermes source and generated library inputs have an empty Ibex patch-set digest, and no file below `patches/hermes/` is a build input.
3. Crate-dependency and module-path checks reject a runtime-kernel dependency on the legacy engine, host composition root, module loader, JSI, C++ bridge, `crates/stdlib::boundary`, `stdlib_ffi`, `stdlib_adapter`, or `crate::host`.
4. Header and link scans reject private/patched Hermes symbols, `currentPrincipalId`, principal-stack collectors, thread-local/root fallbacks, legacy authority globals, and scalar authority dispatch.
5. The closed-world inventory begins from the actual linker/object/entry-root closure recorded in the `GreenfieldFinalArtifactReceipt`; any legacy runtime object, export, or bridge in the linked artifact fails the build.

The clean closure is a security property; disabling legacy code is not isolation evidence.

## 6. Bootstrap and first project entry

The first executable greenfield fixture must use the production sequence, which wraps LLP 0058.000.000 §6.1 without reordering it; no diagnostic shortcut may later become the product bootstrap:

1. authenticate the `HermesInputReceipt` and `GreenfieldFinalArtifactReceipt` (§5);
2. create the kernel runtime generation with the coordinator in `Idle`; the adapter then allocates Hermes with engine job execution disabled, and only the coordinator enables jobs, at step 9;
3. capture exactly the receipt-bound freeze inventory of step 5 (§6.1 step 1);
4. install the construction-private native adapters and receipt-bound `GrantFree` shared surfaces (e.g. `TextEncoder`) as inventoried roots; capture the adapters into unreachable native/loader state; delete every construction-private property and verify deletion and non-reachability (§6.1 steps 2-4);
5. freeze and verify the receipt-bound root inventory, including the shared surfaces, while no engine job, getter, proxy trap, or embedder callback can run (§6.1 step 5);
6. the loader verifies the `ModuleReceipt` against the live `HermesInputReceipt` (§3.3), then mints authenticated module contexts and constructs operation bindings and immutable namespaces through the captured native state (§6.1 step 6);
7. verify the final global/root inventory and engine/job quiescence;
8. the loader invokes only a receipt-bound `FactoryV1` through the adapter with a kernel-issued namespace token; and
9. enable job execution and enter the outer driver from `Idle`.

Steps 3-7 are §6.1's no-project-code/no-job critical section; post-freeze namespaces use captured native state. Any failure destroys the runtime (§3.1 rollback) rather than selecting a compatibility, insecure, patched, or legacy path. Ambient compatibility uses this kernel with one application context and an explicit Web wrapper under LLP 0039/0047, never the legacy runtime under a new name.

## 7. Required vertical slice

Broad API work starts only after one integrated slice, run through `FactoryV1`, the real adapter, kernel, coordinator, and one authenticated module context (G2), proves the difficult boundaries:

1. **`TextEncoder.encodeInto`** -- shared `GrantFree`, bounded inline computation with a borrowed destination range and no serialization.
2. **Timers** -- grant-free but module-bound `ContextRequired` schedule, clear, ref, and unref; deterministic order; retained actor; cancellation; post-callback microtask drainage.
3. **Promise-only `fs.readFile`** -- an async effect with Requested, Discovery, Commit, and Repeat checks over an authenticated VFS generation, worker completion, owner delivery, refusal, cancellation, and teardown.
4. **`HMAC-SHA-256 sign` over an opaque key** -- private resource token, wrong-kind/runtime/generation refusal, non-extractable custody, revocation, and owner-thread host-object release.
5. **Cross-cutting lifecycle fixtures** -- pre-existing microtasks versus ready host tasks, nested drive requests, queue admission failure, duplicate and late producer completion, policy-generation replacement, `Closing`, and the §3.1 barrier with queued jobs and retained slots.

Each item is distinct; missing v1 APIs remain absent.

## 8. Construction sequence and gates

### G0. Public-Hermes feasibility spike

Build the exact upstream pin and prove, using public interfaces only: creation and invocation of factory-compiled source and HBC; the pre/post microtask checkpoints and exception reporting the driver requires; owner-thread host functions and private native closure/host-object state; safe destruction with queued Promise jobs and retained host values; and capture/delete/freeze of the selected root inventory without project code. G0 also delivers the `HermesInputReceipt` schema, its independent validator, and a reproducible receipt for the selected pin (§5).

This is a kill gate: if the public interface cannot implement the contract, Ibex advances to a pin with the primitive, upstreams it, narrows the product contract through an accepted LLP amendment, or retains the patched tier. The adapter never compensates with a private header or local Hermes patch.

### G1. Deny-all kernel skeleton

Implement runtime/context/binding/resource/callback/completion tables, operation descriptors, exact policy generation, revocation ancestry, stable refusals, the single host-task FIFO, the coordinator with its hooks and reservation outcomes, and the teardown barrier (§3.1). Initially every `ContextRequired` operation denies. Run the contract through mock hooks and fake services before binding JavaScript. G0 and this mock-only work may run concurrently; G2 consumes both.

### G2. Integrated vertical slice over one authenticated module

Prerequisites, implemented here and not deferred: the `ModuleReceipt` schema and loader cross-check (§3.3, §5); `mint_context` for one authenticated module principal; namespace construction and production lockdown under §6; and the real coordinator. Then implement §7 without compatibility fallbacks. The slice graduates only when all happy paths, denials, race interleavings, effect-closure checks, and owner-thread lifetime tests pass against the exact `HermesInputReceipt` artifact; it proves one context and does not claim cache keys, imports, or hostile modules.

### G3. Multi-module secure graph

Expand to authenticated multi-module graphs: per-context namespace cache keys, import/re-export bearer tests, cross-module delegation and Rust-derived attenuation, malicious-module authority-discovery and poisoning fixtures, and explicit refusal of unsupported graph/artifact shapes.

### G4. Audited v1 expansion

Classify each LLP 0059.000 API as `AdoptLeaf`, `WrapService`, `RewriteBoundary`, or `Absent`, record the classification in the graduation manifest (§10), and port one operation family at a time into the greenfield closure. Capability-bearing families need their complete transport and stage path before publication; pure APIs may land independently.

### G5. Product posture, platform, and owning-contract closure

Implement the LLP 0039 posture matrix, negative selectors, artifact disclosure, and a source-built `HermesInputReceipt` (§5) for every platform the selected tier requires (the initial production tier requires macOS, iOS, Android, Linux, and Windows); evidence from one platform does not bless another. The owning-contract gates are the accepted LLP 0013, 0039, 0040, and 0059.000 amendments of LLP 0058.000 §8.7 plus the LLP 0021 amendment of §1. Policies needing patched deputy or LLP 0040 extension semantics remain ineligible for vanilla.

### G6. Artifact-level cutover

The greenfield profile becomes a production option only after every manifest entry passes for its bound tier (§10), the `GreenfieldFinalArtifactReceipt` is bound and equal, and all LLP 0058.000 §8 gates hold for that tier. A consumer selects the whole artifact before runtime creation, after its composition root authenticates the product-pinned receipt and tier identities; it never cuts over individual operations inside a legacy runtime. Making greenfield the default is a later product decision; the patched runtime remains available while any supported posture or extension contract requires it, and its deletion follows only after repository-wide reference, build, and product inventory proves no supported artifact depends on it.

## 9. No-hybrid invariant

> A greenfield runtime links and executes exactly one runtime kernel, one runtime loader, one engine adapter, one module bootstrap, and one effect path for every reachable operation. The legacy runtime is not a fallback service.

Specifically forbidden: forwarding an old global into the new dispatcher; asking the legacy adapter for a current principal or constrained stack; resolving an unsupported module or API through the old runtime; sharing a callback, Promise, native token, resource slot, or engine value between families; a second legacy authorization controlling transport beneath the new kernel; and shipping an incomplete secure profile because tests exercise only implemented operations.

Shared process-wide platform pools are allowed only when their client API is authority-neutral, requests carry already-authorized exact resource facts, and no state crosses runtime or policy generations. The process-global `Host` singleton, its `host::abi` context maps, and its authenticated VFS generation registry are not eligible pools and may not be wired beneath a greenfield runtime.

## 10. Tier definition, graduation manifest, and evidence

**Tier definition.** `ibex/greenfield-tier-definition/1` is a checked-in, product-pinned authority, independent of any manifest, defining a tier identity and its immutable minimum required LLP 0059.000 API/operation set, permitted `Absent` entries, module formats and graph shapes, application corpus, target triples, postures, and feature sets. A same-tier successor binds its predecessor's digest and proves a superset; any reduction requires a new tier identity, explicit product selection and disclosure, and full G6. The initial production tier requires the five G5 platforms. The composition root selects only the product-pinned tier, never an artifact's self-description.

**Graduation manifest.** A greenfield artifact is secure-selectable only with a `GraduationManifest` bound by the `GreenfieldFinalArtifactReceipt` (§5) that names its tier-definition digest and enumerates its evidence inputs exactly:

- every required LLP 0059.000 API/operation with its G4 classification, `Absent` only where the tier permits;
- the module formats and graph shapes admitted by the receipt-bound `FactoryV1`/HBC builder;
- the tier's application corpus, run from shipped HBC on every tier target, with the claimed postures, target triples, and feature sets;
- the final source/link closure digests, equal to the final receipt's;
- the negative scans; the complete LLP 0058.000.000 suite through both the Hermes adapter and a mock adapter; the closed-world inventory with one disposition per sink; adversarial module, delegation, poisoning, observable-coercion, stale-token, revocation, queue-race, and teardown fixtures; exact Requested/Discovery/Commit/Repeat evidence; receipt-mismatch refusals; and negative packaging tests proving an oracle/incomplete receipt cannot enter a secure product; and
- the LLP 0021 target-advertisement and conformance reports generated under the §1 amendment.

Every listed entry must pass, not "every implemented entry". A manifest may add entries beyond the tier, but any artifact or manifest change reruns all listed evidence on the new digests. Performance measurements against explicit budgets are not security proof, and differential results against Ibex 1 are compatibility evidence that cannot waive a refusal, provenance, inventory, or lifecycle gate.

## 11. Remaining choices

1. The exact upstream Hermes commit is selected only after G0 produces a reproducible `HermesInputReceipt`.
2. Physical crates, directories, FFI layout, and the Rust/C++ ABI may vary if the §3 dependency graph and ownership are mechanically enforced; §5 scans match denylist prefixes only.
3. The first development target may be chosen for iteration speed, but G5 requires every platform of the selected tier.
4. Native runtime extensions remain patched-tier-only until an accepted LLP 0040 amendment defines the vanilla carrier; this Spec does not design that replacement.
