## Security Delta Assessment

## Verdict

REGRESSES — 2 MATERIAL regressions: production commit is not structurally gated, and commit-fence failures do not quarantine.

## Material Findings

1. **MATERIAL — The native commit primitive bypasses the structural production/type-state boundary.** `HotRevisionSurfaceV1` accepts a caller-supplied `GenerationMode`; production refusal occurs only when the caller selects `Production` ([hot_revision.rs:34](/Users/ccheever/projects/ibex-wt/0055-s3/src/module_loader/hot_revision.rs:34), [generation.rs:1140](/Users/ccheever/projects/ibex-wt/0055-s3/src/module_loader/generation.rs:1140)). The public C ABI accepts only runtime, nonce, generation, and bare record IDs; it checks drive ownership, pinning, record state, SourceId, and slot ownership, but never boot mode, authority stamp, immutable ceiling, or `ReadyToPublish` provenance ([exact_runtime.h:844](/Users/ccheever/projects/ibex-wt/0055-s3/include/exact_runtime.h:844), [hermes_module_runner.cc:3172](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:3172), [hermes_module_runner.cc:3226](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:3226)). Consequently, owner-thread native code holding the runtime and nonce can mutate a production graph independently of the typed surface. JS/realm callers cannot reach it, and off-owner/reentrant callers are refused. Additionally, native records retain SourceId but not the factory’s principal or compartment, so commit cannot independently prove predecessor/successor attribution parity ([hermes_runtime_internal.h:239](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_runtime_internal.h:239), [hermes_runtime_internal.h:280](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_runtime_internal.h:280)). This violates LLP 0055’s structural production refusal ([LLP 0055:909](/Users/ccheever/projects/ibex-wt/0055-s3/llp/0055-hot-revision-intra-generation-updates.spec.md:909)).

2. **MATERIAL — The supposedly no-fail commit fence can fail after publication without quarantining.** The engine publishes successors, retargets slots and forwarding, releases contexts, and erases predecessors first ([hermes_module_runner.cc:3284](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:3284)). It then performs fallible JSI array/string allocations and calls the JavaScript invalidator; any exception merely returns `EXACT_RUNTIME_DRIVE_ENGINE_ERROR` ([hermes_module_runner.cc:3309](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:3309), [hermes_module_runner.cc:3326](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:3326)). The Rust wrapper converts that into an ordinary error and does not quarantine ([module_runner.rs:1029](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/module_runner.rs:1029)), even though a quarantine primitive exists ([hermes_runtime.cc:3015](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_runtime.cc:3015)). The Rust staging seam has the same structural problem: it adopts the graph before applying a publicly constructible arbitrary `FnOnce()` activation action ([hot_revision.rs:133](/Users/ccheever/projects/ibex-wt/0055-s3/src/module_loader/hot_revision.rs:133), [hot_revision.rs:254](/Users/ccheever/projects/ibex-wt/0055-s3/src/module_loader/hot_revision.rs:254)). An allocation failure, loader exception, or activation panic can therefore leave a half-published runtime Running, contrary to the mandated quarantine/recreate behavior ([LLP 0055:633](/Users/ccheever/projects/ibex-wt/0055-s3/llp/0055-hot-revision-intra-generation-updates.spec.md:633)).

## Advisory Notes

- Carrier retirement is safe against double-decrement and UAF: aggregate counts are prevalidated, tables leave the map only at zero, and extracted factories have independent `shared_ptr` ownership ([hermes_module_runner.cc:230](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:230), [hermes_module_runner.cc:244](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:244), [hermes_module_runner.cc:2325](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:2325)). However, CommonJS records carry no carrier key or occupancy reference, so CJS-only and factory-only tables are not retirement-complete ([hermes_runtime_internal.h:334](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_runtime_internal.h:334), [hermes_module_runner.cc:2435](/Users/ccheever/projects/ibex-wt/0055-s3/src/engine/hermes_module_runner.cc:2435)). This is bounded by the admitted carrier set in the intended path, but remains a retention/DoS hardening gap.
