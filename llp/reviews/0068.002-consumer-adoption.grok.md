## Received review

The package is implementable as one adoption program. Ibex keeps protocol, grants, byte limits, and lifetime notifications. Exact keeps scheduling, budgets, codecs, and pickers. Nothing here requires a new ownership model before code. Three seams will cause rework if an implementer guesses: when the whole-request deadline starts relative to Exact's upload park, how `CommitStarted` is proved in the consumer, and treating the patch ledger as a diff against Ibex `3c7a17a`. These remain Drafts. This review does not accept them.

Checks against the pinned trees, with no tests run: in Exact `075b946`, `BlockingAdapter` reports a refused spawn inline during activation; Darwin delivers refusal and completion on the session queue and can overlap `activate`'s return; `CommitGate::abandon` blocks while a write holds the gate; the async executor arms `timeout_ms` during `exactBodyFrom` sizing, removes that timer when the upload parks, and arms a full window again on the first hop. Ibex `3c7a17a` is the Android bundle commit.

## LLP 0068.000 — READY WITH IMPLEMENTATION NOTES

The prepare, record, then activate split is sound. One terminal outcome, plus separate signals for that outcome, each hop's physical end, and the last upload release, matches the prototype. A refused worker is a synchronous admission error: no accepted exchange and no transport callback. Spawning a thread to hide that refusal would break the contract.

Pin the deadline arm point before the timeout slice. The Exact executor arms the caller timeout while sizing a file body, removes it if the job parks, and arms the full duration when the first hop starts. Later hops do not arm again. "After its initial capacity wait" can be implemented as forbidding that second arm. The arm point that agrees with this RFC and with Exact LLP 1120 is: sizing and parking may use Exact's own timer; the network deadline starts at the first accepted activation; it then covers platform queueing, later hops, and waits between hops; parking does not restart it. Race tests should assert that point. Starting the same clock at the first capacity grant, and keeping it across a park, would change the executor's shipped timeout behavior and needs an explicit decision.

Prove admission refusal, cancel-before-activate, and a callback that overlaps `activate`'s return on a fake transport before adding the Apple adapter. `BlockingAdapter` still copies the body; the shared immutable buffer and last-release rule have to hold for that adapter too. A per-hop transport timeout stays a backstop. It is the whole-request deadline only when the consumer's `AbortSignal` says so.

## LLP 0068.001 — READY WITH IMPLEMENTATION NOTES

Admission before the provider runs, leases pinned to retained handles, physical paths kept out of guest errors, and confirmed abandonment meaning the destination write neither starts nor finishes, are a sound replacement for the blocking commit gate. Today's `abandon` waits on the write lock and can observe `Written`. Returning `CommitStarted` immediately, and waiting for publication outside shared locks, is the right adaptation. A private temporary write may finish after abandonment only because it never publishes the target.

The consumer proof has to include the loss: cancellation returns `CommitStarted`, publication then succeeds, the previous target changes, and Snapback consumes that output. An abandoned output that Snapback ignores does not cover the successful publication the old blocking wait was there to reveal. A zero worker count means the worker has returned. Cancellation success is the per-work state.

Check the compression opcode and TypeScript declaration against this Ibex ABI before assigning them. Guest `AbortSignal` stays out of the contract until it reaches the work handle. The 16 MiB figure is this consumer's serialized `readFile` envelope. Rust read caps and image-slot limits are configured separately. Decoded-pixel and scratch bounds stay the codec provider's obligation, which the RFC already states.

## LLP 0068.002 — READY WITH IMPLEMENTATION NOTES

The unit of completion is an upstream implementation plus a consumer run of the same behavior. Section 3's order matches the RFCs: bounded reads, then grammar, then documents, then codec and work identity together; blocking transport and typed redirect errors, then shared fetch and deadlines, then Apple. Follow that prose and LLP 0068.000. The patch-13 evidence cell lists Apple tests ahead of the bounded adapter.

The ledger is evidence from base `7f77c82`. Row 8's Android bundle commit is already Ibex `3c7a17a`, so that row is authenticated distribution, install, and offline use. Replaying the ledger as a patch will fight this baseline. Row 7 waits on the deadline arm point above. Row 11 is the compression worker count. HTTP permit release stays on the fetch signals in LLP 0068.000.

Resolve grant grammar with shared fixtures and no Ibex dependency on Exact before rows 4 and 5. A neutral grammar crate is still an open implementation choice. Exact's extra application vocabulary stays in Exact. The phase A stream amendment stays on Exact's runner-owned interface and leaves blocking `Fetch::stream` as it is. LLP 0071's borrowed clock stays out of the network deadline.
