**Type:** RFC
**Status:** Accepted
**Systems:** Rust Stdlib, Host ABI, CapSec, Filesystem, Bindings
**Author:** Codex for Charlie Cheever
**Date:** 2026-10-13
**Accepted:** Charlie Cheever, 2026-10-13, by directing implementation of these three documents.
**Revised:** 2026-10-13 (one Astra Max and Grok 4.7 xhigh approach review; file identity and completion accounting clarified)
**Implementer:** Root Codex orchestration under Charlie's 2026-10-13 commission; the slices below are authorized implementation work.
**Related:** LLP 0068 (Rust and borrowed-runtime consumers), LLP 0067 (authority), LLP 0059.000 (filesystem operations), LLP 0068.002 (consumer-patch adoption)

## 1. Proposal and boundary

Support two optional embedder services: resolving a person-chosen document
to an owned filesystem capability, and transforming image bytes through an
embedder codec. Ibex keeps grant admission, contained filesystem operations,
byte bounds, and the decision permitting a cancellable operation to write.
The embedder keeps pickers, document/session identity, codec implementation,
and its executor. Both services work through `host::Host` without an engine
and through `bindings::Context` with the same Rust implementation.

This refines LLP 0068 rather than creating an application storage layer.
Do not add a dependency on Exact, `exact-grants`, a particular codec, or an
async runtime. Do not generalize this into a provider for every filesystem
operation. Existing app directory handles are the implementation foundation.
Ordinary `writeFile` and `appendFile` retain their existing semantics; the
strong abandonment contract below applies to explicitly tracked transform
and staged-publication work.

## 2. Evidence and what is not yet built

Exact carries reusable pieces in its [patch ledger][patches]: document
resolution (4/5), compression and its commit gate (9), bounded file access
(10), work accounting (11), and bounded filesystem results (12). Its
[document implementation][documents] retains directory handles, including a
selected file's parent with only the selected leaf addressable. Its
[compression implementation][image] passes bytes to a codec, then holds a
per-call gate across the atomic write. Abandonment can wait for that write;
an already-written result remains registered until completion is taken.

These are consumer evidence, not upstream completion. Patch 4's shared grant
crate is Exact policy: Ibex should implement the needed logical namespace in
its own grant representation and verify a shared fixture set at adoption.

Exact's [LLP 1108.001][media] is explicitly Draft/NOT READY. Its proposed
staged-download publication, object URLs, and memory ownership are not an
accepted Ibex contract or a shipped patch. In particular, that draft allows
some guest aborts to drop a reply while host work continues. Such an abort
must never be described as confirmed abandonment under this RFC. This RFC
supplies a reusable publication primitive; it does not adopt `exactSaveTo`,
Snapback cache policy, object URLs, or the draft's browser rules.

## 3. Chosen-document provider

Add an optional `Documents` service installed once on a Host/Context. Its
conceptual operation is `resolve(logical_path, access) -> DocumentLease`.
Names and concrete Rust types may be settled in the implementation; the
following ownership and admission requirements are the API contract.

- Parse a `doc:/<handle>/<name>/...` path into validated components. Reject
  dot traversal, empty interior components, NUL, and alternate separators.
  Document, app, and native absolute prefixes are distinct namespaces.
  Prefix matching compares components; `doc:/1` never admits `doc:/10`.
- Admit every required `fs.read`/`fs.write` grant before invoking the
  provider, inspecting its table, statting, opening, or allocating a file
  payload. The provider receives the requested access so a read-only
  selection cannot gain write authority from a broad manifest grant.
- A lease is either a synthetic, read-only root containing its one selected
  entry, or an owned directory handle plus a validated relative name and
  an owned lifetime guard. A selected file permits only its leaf; a selected
  directory permits descendants. No physical path is returned to the guest.
- Ibex opens descendants relative to retained handles, rejecting symlinks
  and Windows reparse points at every descendant component. Metadata and
  reading use the same opened file. Moving/replacing the retained directory's
  ancestor pathname cannot redirect the capability. A selected file identifies
  a leaf name in its retained parent, not an immutable inode: replacing that
  leaf changes what a later operation opens, subject to the same no-follow
  and regular-file checks. This permits atomic save at that selected name.
  Explicitly following a symlink when the
  person selects its target is the provider's trusted minting operation.
- The provider owns handle minting, session checks, forgetting, and any
  platform security-scope guard. A queued operation resolves when it starts,
  so a forgotten selection is refused. A successful lease pins its handle
  and guard until work actually ends, even if delivery has been abandoned.
  Forgetting prevents new leases; stopping an existing operation requires
  its work handle. Handles must not be reassigned within a provider lifetime;
  a new provider/session cannot be installed into an old endowment.
- Errors carry a stable kind and logical path; provider diagnostics and OS
  failures must not disclose physical paths in guest errors. Provider callbacks
  are never invoked under task-registry or completion-queue locks.

Start with the consumer's existing operation set: read, write, append,
atomic write, stat, list, mkdir, and nonrecursive removal of descendants.
Removing the selected entry itself, rename, copy, and realpath remain refused.
An absent service or unsupported native platform returns Unsupported.
General document-to-app copy and image compression on documents can be
considered later; the first compression slice accepts `app:/` paths only.

## 4. Bounded access and image work

Expose a grant-checked, handle-relative regular-file reader to Rust consumers,
with an explicit limit and cancellation observation between chunks. A raw
opened-file escape hatch for trusted Rust code must document that the caller
owns subsequent read scheduling and bounds; JSI exposes no native handle.
Read size from that same opened handle as an early refusal, then enforce the
limit on actual bytes. File growth or a misleading size cannot evade it.

For serialized `readFile`, the default envelope bound is the consumer's
16 MiB. Derive the raw-byte maximum from base64 expansion and fixed JSON
overhead; count directory names at their encoded size before retaining them.
Read at most one probe byte beyond the raw limit, use checked arithmetic,
and retain the final serializer backstop. An explicit Rust byte limit may
differ from the JSI envelope limit; it does not imply a larger JS result.
Recursive removal uses bounded batches independent of a read-result limit.
Apply the same rules on native, app, and chosen-document paths on Unix and
Windows, including same-handle directory refusal and ACL error propagation.

The optional image codec receives input bytes, requested dimensions/output
bound, and a cooperative cancellation/deadline view. It receives no paths,
grants, or destination handles. Its owned result contains encoded bytes and
dimensions. Missing codecs refuse before reading source bytes. Both source
read and destination write authority are admitted before provider work.

Ibex rejects unreasonable/overflowing dimensions and byte limits before
input allocation. The codec contract must bound decoded pixels, scratch
memory, and encoded output before allocating them; rejecting an oversized
returned vector alone does not bound provider memory. Initial compatibility
uses Exact's 64 MiB encoded-input ceiling and 20-second trial-start budget;
codec-specific pixel/scratch limits are declared by the installed provider.
An expired budget permits no new decode/encode trial. It cannot interrupt an
OS call or a codec already executing; §5 states that limitation explicitly.

Input/output allocations are charged to a bounded work slot until released.
Settled results awaiting collection retain bounded completion slots, including
their payloads and outcome records, until taken or explicitly discarded.
Returning a worker slot does not release this completion charge.
Limits on work count and per-job memory are configured before installation;
the consumer qualification records their concrete values. A full budget
refuses admission before allocating payloads. Provider code is trusted to
honor its workspace limits; Ibex validates returned dimensions and size too.

## 5. Work identity and the cancellation decision

Give each tracked operation an owned work handle registered before dispatch,
with an identity unique to the Context/Host owner generation. Keep worker
lifetime separate from completion-delivery lifetime. A retired waiter can
cancel only work it owns; it cannot enumerate and abandon a newer generation.

| State | Cancellation result and permitted effects |
| --- | --- |
| Queued | Confirm Abandoned; it cannot start provider work or write. |
| Running | Confirm Abandoned if it wins before CommitStarted; signal the provider and prohibit destination mutation. Computation may still finish. |
| CommitStarted | Return CommitStarted immediately; cancellation cannot claim the destination will remain unchanged. Observe the eventual commit result. |
| Settled | Return the recorded terminal outcome; cancellation cannot turn a committed write into an abandoned failure. |
| Abandoned | Idempotent confirmation; late results release resources and cannot publish. |

Prepare output privately. For a staged file, create a random exclusive file
in the pinned destination parent, using no-follow semantics; perform bounded
writes and sync outside shared locks. Under one short per-work lock, test
owner validity, cancellation, and deadline, then make the sole transition
from Running to CommitStarted. Publication happens afterward through that
pinned parent. The same lock orders abandonment and this transition.

**After confirmed Abandoned, no destination write or publication from that
operation can start or finish.** A cancellation that loses to CommitStarted
has not confirmed abandonment. It must not produce a timeout/failure claiming
that no write occurred. CommitStarted settles with the actual publication
result, even beyond the original deadline. Keep that outcome observable until
taken or explicitly discarded, including when publication completed before a
waiter noticed it. Detaching a JS promise may discard delivery, not history.

For compression, the final implementation may stage the encoded bytes before
the transition, or reserve the complete atomic write at CommitStarted. In
either case there is exactly one reservation and the outcome rule is the
same. Stage cleanup and an already-running write to a private temporary file
may finish after abandonment; they never touch the target. Failure before
publication leaves the old target intact. The promise is atomic visibility,
not power-loss durability or rollback of a completed publication.

Do not hold a global work registry, executor state lock, or JSI lock across
filesystem calls, codec calls, cancellation waits, or user callbacks. The
shipped Exact gate's blocking abandonment needs adaptation to this immediate
CommitStarted result, with an embedder wait performed outside shared locks.

The worker budget counts a worker until it actually returns, even after an
Abandoned reply. Bound queued jobs as well as executing jobs; stuck workers
consume their slots and eventually cause admission refusal rather than new
threads. Teardown closes admission, abandons cancellable work, drops guest
roots/delivery, and retains native leases for any remaining workers. Neither
a deadline nor Context teardown promises to kill a stalled syscall or codec.
Expose outstanding worker count plus per-work state for testing and orderly
drain; a count of zero is evidence of quiescence, not the cancellation API.

## 6. Rust and borrowed-JSI integration

Host endowments and Context adoption carry the same configured services and
limits. Rust callers execute on their chosen executor, retain the work handle,
and observe its cancellation result directly. No bindings feature is needed.
JSI registers work on its owner thread before enqueueing and delivers outcomes
only through the existing task queue. The codec and document provider never
touch JSI. The adapter must detach its roots before the runtime is destroyed.

Compression can retain Exact's `fs.compressImage` shape through STORAGE, but
its operation number and TypeScript declaration must be checked against the
current ABI before assignment. A missing codec produces an explicit refusal.
Any advertised guest cancellation must reach this operation's handle; merely
rejecting a promise is insufficient. Until that connection exists, document
only embedder-controlled abandonment and do not promise guest AbortSignal
semantics for the operation.

## 7. Implementation slices and consumer evidence

1. **Bounded reads and results first.** Port ledger 10/12 without provider or
   codec dependencies. Test a growing file, large/escaped directory entries,
   denied reads, and write-only recursive removal. Qualify Exact's file upload
   and storage envelope through the Rust and borrowed-runtime doors.
2. **Chosen documents.** Add the local grant namespace, minimal service/lease,
   and Unix/Windows handle execution. Prove denial before provider access,
   cross-session refusal, forgotten queued work, root replacement, symlink and
   reparse escape refusal, same-handle directory detection, and retained guards.
   Exact opens and atomically saves a chosen file after its parent is renamed;
   another session cannot use the handle. Keep picker policy in Exact.
3. **Tracked image work.** Add the codec service and per-work state machine.
   Use controlled barriers to race abandonment before dispatch, during decode,
   before publication, during publication, and after completion but before
   delivery. Check the old target, late-write absence, one terminal outcome,
   resource release, stale waiters, stalled workers, and bounded admission.
   Exact abandons a media compression during answer replacement; Snapback's
   upload path never consumes an output reported as abandoned. Teardown runs
   while native work remains to prove guest roots are not retained or touched.
   Also prove the losing cancellation: it immediately reports CommitStarted,
   publication succeeds and changes the old target, and Snapback consumes that
   successful output. Ignoring an abandoned output does not prove this case.

Each slice carries its LLP amendments and focused tests; run workspace clippy
and `./ref-check` before landing. Patch retirement requires consumer evidence
on the adopted revision, not just passing Ibex tests. Staged HTTP downloads
are a later consumer of §5 after their own design is settled. Implementation and qualification are recorded below; status remains Accepted until
consumer adoption evidence is complete.

## 8. Implementation record (2026-10-13)

The implementation slice adds bounded filesystem reads/results, independent
`doc:/` grant parsing, retained `DocumentLease` capabilities, and `ImageJob` work
through both Host and Context. Documents resolve at execution with explicit
Read/Write access and path-free typed provider errors. A selected file is a
leaf name in its retained parent. Unix/Windows native implementations refuse
descendant symlink/reparse traversal.

`ImageCodec` declares decoded-pixel and scratch bounds; its cooperative
`WorkControl` checks cancellation and the 20-second trial deadline. Default
work limits are four queued/executing jobs, sixteen retained completions,
256 MiB per-job reservation ceiling, 64 MiB source and output ceilings, and
16,384 maximum dimension. Codec scratch/pixel bounds must be installed
explicitly. An `ImageJob` is admitted before dispatch. Each owned `WorkHandle`
has a generation plus sequence identity; cancellation returns Abandoned,
CommitStarted, or the recorded outcome. Returning workers and collecting
completions release different charges. Missing codecs refuse before reading.

Destination parents are pinned before codec work. The publication transition
reserves the complete atomic write, then releases the per-work lock before
filesystem calls. `execute_with_commit_observer` offers trusted native
instrumentation at that decision for deterministic consumer qualification.
Ordinary write/append semantics are unchanged. Opcode 121 is the async
`fs.compressImage` operation and returns the existing tab-separated
width/height/size record; cancellation is embedder-controlled through owned
handles, with no guest AbortSignal claim.

Host/Context `ResultLimits` can tighten the default 16 MiB serialized envelope
(minimum 16 bytes). A stack-scoped internal execution budget reaches the
synchronous platform readers/enumerators and restores across nested calls or
unwinding; it is not process-global configuration. Explicit Rust
`read_bounded`/`read_capped` accepts its own raw-byte ceiling and cancellation
check. Read sizes and regular-file checks use the actual opened handle.

The first checkpoint's native Linux engine-free suite passed all 178 tests on
2026-10-13 (Rust 1.93.1, four jobs/test threads). Further regressions exercise
growing files, base64/escaped-name envelope accounting, provider and commit
observer panics, borrowed-JSI completion delivery, and teardown while a codec
is blocked. Native Windows tests include same-handle directory refusal and ACL
denial with the fixture DACL restored. Those additions and bindings/platform
qualification are pending at this checkpoint; no consumer patch retirement is
claimed here.
