**New findings and remaining defects in the fix**
1. **MATERIAL — Detach checks do not enforce the promised stop between jobs or callbacks inside an entrance.**
   [`checkpoint()` at install.cc:2344](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/bindings/install.cc:2344) calls an unrestricted drain and checks `alive` only after it returns. With the fixture’s probe installed, this sequence exposes the gap:
   ```javascript
   HermesInternal.enqueueJob(function () { detachFromJs(); });
   HermesInternal.enqueueJob(function () { log.push("late"); });
   ```
   Detach changes adapter fields, but does not stop the engine’s active drain or remove its remaining jobs. The second job can run before line 2345 observes detach. This applies to either checkpoint.
   The same limitation exists inside error dispatch: [`report_error` at install.cc:2291](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/bindings/install.cc:2291) enters a JavaScript dispatcher whose [listener loop at events.js:381](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/bindings/events.js:381) has no lifecycle check. A first error listener can detach; subsequent listeners still run. Likewise, [`settle` at install.cc:2131](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/bindings/install.cc:2131) can enter a caller-replaced `Error` constructor and then call the stored rejection function without revalidating lifecycle.
   These are stronger failures than merely allowing the currently executing frame to return. They contradict [r4:150](/Users/ccheever/projects/ibex2-0071-impl/llp/0071-timers-and-a-clock-for-a-borrowed-runtime.rfc.md:150), the [public header:378](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/include/ibex2_jsi.h:378), and the governing prohibition on starting another callback/job after Closing at [LLP 0058.000.000:590](/Users/ccheever/projects/ibex2-0071-impl/llp/0058.000.000-rust-capability-context-and-engine-adapter.spec.md:590).
2. **MATERIAL — The new detach regression does not establish its central no-further-JavaScript claim.**
   The test queues `late` at [borrowed_timers.rs:578](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2-runtime/tests/embedding/borrowed_timers.rs:578), but its assertions only require a log starting with `t` and containing no `u`. Consequently, `t,late` passes. The later cycle’s no-op is useful, but does not establish what happened inside the original cycle.
   Require the exact log, add detach from both checkpoints and error listeners, and exercise Context release while the drive hold remains active. The current test leaves that ownership case untested.
3. **MINOR — The huge-duration wheel test passes with the old truncating conversion.**
   [timers.rs:344](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/stdlib/timers.rs:344) uses `Duration::MAX`. Its microsecond value is:
   `2^64 × 1,000,000 − 1`
   Truncating that to `u64` already yields `u64::MAX`; adding the test’s positive origin also saturates to `u64::MAX`. Thus the old implementation also returns `None` at `u64::MAX - 1`.
   Use an overflowing duration whose truncated microseconds become a smaller value—for example `Duration::from_secs(u64::MAX)`—and check the resulting deadline.

**Other requested paths**
The retained-state ABI is balanced. [`clone_queue()`](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/task.rs:1844) adds one strong reference. Successful acquisition transfers that reference into the returned raw token. Failed acquisition drops the temporary Arc and leaves the existing drive flag held. Null acquisition returns null. [`end_drive()`](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/boundary_abi.rs:1303) accepts null as a no-op; otherwise it reconstructs exactly one Arc, clears the flag, and drops that reference. Its safety documentation could explicitly allow null.
`DriveHold` is noncopyable and releases on ordinary returns and C++ unwinding. Detached entry returns acquire nothing; nested calls own no token to release. The retention is storage retention, not an owner lease, so it does not postpone owner-triggered shutdown.
A saved queue address alone is **not safe after its last owner/reference disappears**. `begin_drive` dereferences Arc storage through `increment_strong_count`; it cannot validate an already-freed pointer. Its documented live-pointer precondition remains necessary. An already-acquired drive token protects its own eventual release after detach and Context drop.
For **a callback that detaches and then throws**, `deliver_next` enters its catch at [install.cc:2396](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/bindings/install.cc:2396). `report_error` immediately rejects the null runtime, and the nested catch falls back to the native reporter. It does not dereference the null runtime or dispatch a JavaScript error event. Delivery returns true, the post-checkpoint immediately refuses, and the hold releases. This path differs from a detached checkpoint throw, which is discarded by the lifecycle check.
Detach during admission’s synchronous wake also avoids a null dereference: `deliver_next` subsequently passes the now-null queue to `ibex2_take_task`, which returns no task. Native admission may finish its current loop; the adapter starts no task or checkpoint afterward.
The **subscription-lock countdown is correct**. Scheduling occurs before arming. After `countdown.store(2)`, admission consumes the first read and timer take consumes the second. Publishing then acquires the subscription registry through [task.rs:1195](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2/src/task.rs:1195). A regression moving `timer_taken` before `drop(subscriptions)` would deadlock. The positive-count guard prevents subsequent reads from decrementing zero. The watchdog bounds this targeted deadlock by aborting the whole test process after 30 seconds; it does not bound the separate original wheel test or setup before it starts.
The **`HermesInternal.enqueueJob` test is meaningful**: its raw jobs bypass Promise reaction containment, both checkpoint failures must produce the expected error events, jobs behind them must run, and the next cycle must acquire the flag. The fixture’s [evaluation function](/Users/ccheever/projects/ibex2-0071-impl/crates/ibex2-runtime/tests/embedding.cc:279) does not drain those jobs beforehand. It does not test engine timeout behavior or detach during recovery.
The run-count and short-interval wheel tests meaningfully check their thresholds. Duration conversion and microsecond saturation look correct by inspection. The new pre-checkpoint, unclocked sealing, far-origin, exact denied-WebSocket log, and JavaScript reconnect-count assertions also address their respective earlier weaknesses.
