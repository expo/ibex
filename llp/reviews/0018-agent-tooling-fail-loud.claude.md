## Overall assessment

Revise and stay `Draft` — concurring with the OpenAI review.

The governing rule is the right abstraction and the highest-priority bug (item 1) is
real in the current checkout. I verified C-1 through C-4 independently and all four
hold. Beyond endorsing them, I found one sharper defect: the plan's own evidence for
item 2 miscounts the test layout in a way that, if implemented literally, would turn
the anti-silent-green wrapper into a *new* silent-green surface. I would fix that
plus C-1–C-4 before implementation.

## Strengths

- **The governing rule generalizes cleanly.** "Exit 0 lied about the postcondition"
  covers symlinks, zero tests, stale generated bytes, and missing wrapper binaries
  under one testable predicate, and item 8 turns it into a forward checklist so the
  class doesn't silently regrow. This is the durable core of the document.
- **Item 1 matches the live script exactly.** `repo_root` is anchored to
  `BASH_SOURCE` (`scripts/link-worktree-artifacts.sh:16`), the default source is the
  first `git worktree list` entry (`:34`), and the run prints `Done: N linked`
  (`:73`). The destination-resolution fix is correctly targeted.
- **Constraints section is load-bearing, not decorative.** It explicitly forbids the
  tempting-but-wrong fix (a shared mutable `CARGO_TARGET_DIR`) and preserves the
  hermetic no-bun-in-normal-build invariant, which is exactly where an
  implementation would be most likely to cut a corner.
- **The sharp-edges appendix is high-value operational memory** — the `extern "C"`
  rlib-drop linkage note and the three-dot merge-base diff note are precisely the
  repeated small failures that belong next to the playbook.

## Concerns

I verified and concur with the OpenAI review's **C-1 (item 5 warning-only is
silent-green for agents), C-2 (item 7 skip rule too broad), C-3 (test-wrapper target
selection), and C-4 (item 1 required-artifact semantics)** — I won't restate them.
Two additions:

- **CL-1 (high) — Item 2's evidence miscounts the lib crate, and its proposed
  default would silently drop 63 binary tests.** The plan states the bulk of the
  suite is "17 `mod tests` files under `src/`" as evidence for scoping to the lib
  crate. Census: those 17 files are **9 lib files + 8 files under `src/bin/ibex/`**,
  and the binary target holds **63 `#[test]`/`#[tokio::test]` functions**
  (`agent_logs.rs`, `runtime.rs`, `main.rs`, `subprocess.rs`, `cdp/mod.rs`,
  `cli.rs`, `engine/hermes.rs`, `repl/mod.rs`). So the `[observed]` evidence folds
  binary tests into the lib count, and item 2's proposed default — "lib +
  integration tests, not `--bin` alone" — would run **zero** of those 63 bin tests.
  An agent verifying a `src/bin/ibex/` fix through the new wrapper would get a green
  that ran none of the relevant tests: the same silent-green the wrapper exists to
  kill, reintroduced by the wrapper itself. This is the deeper form of C-3.
  **Resolves when:** the default target set is Cargo's full package test set
  (lib + bin + integration), narrowed only by an explicit `--scope lib|bin|test|all`;
  and the Motivation's "17 lib" evidence is corrected to "9 lib + 8 bin" so the plan
  doesn't reason from a wrong premise.

- **CL-2 (medium) — Item 5 is written as "add a warning," but a warning already
  exists and fires on every hermetic build.** `build.rs:474-478` already emits
  `cargo:warning=Ibex build: using vendored generated artifacts from …`
  unconditionally in the `standalone` path. Item 5 as written risks layering a
  second warning on top, which (a) is not a *staleness* signal — it fires whether or
  not `src/` is newer — and (b) trains agents and humans to ignore build warnings
  (alert fatigue), which actively erodes the fail-loud posture the plan is defending.
  The novel, valuable part of item 5 is the **mtime/hash comparison of `src/`
  generated inputs against `vendored-generated/**` outputs**, gated so the agent path
  is nonzero-exit (this is also C-1). **Resolves when:** item 5 says explicitly that
  it replaces/subsumes the existing always-on `cargo:warning` with a real staleness
  comparison, so the loud signal fires only when `src/` is actually newer than the
  embedded bytes — not on every build.

## Suggestions

- Fold the corrected count directly into the Motivation prose for item 2, not just
  the plan section — the wrong number is currently the load-bearing justification.
- For item 5's path set, include `src/builtins/helpers/runtime-module-manifest.cjs`
  and `vendored-generated/builtin_manifest.generated.rs` explicitly — the existing
  `check-generated-drift.sh:35` already pairs them, so the staleness check should
  cover the same inputs rather than a subset.
- The `run-tests.sh` wrapper (item 2) should surface *which* scope it ran in its own
  output ("ran 214 tests across lib+bin+integration"), so the agent's evidence names
  the coverage, not just a pass/fail — this makes CL-1's failure mode observable even
  if the default is later narrowed.

## Open questions

- Should item 2's wrapper be the *only* sanctioned agent test entry point, or should
  a broader `verify-agent.sh` compose it with the item-5 strict stale check and the
  item-6 timeout wrapper so "one command verifies correctly" is true end to end?
- Given the Claude/OpenAI reviews now converge, is a third-family (Gemini) pass worth
  the latency for a Plan of this stakes, or is two-family coverage plus an
  implementation-time review of the actual shell/build patch sufficient?
