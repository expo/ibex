# LLP 0000: Ibex

**Role:** Root

## Overview

**Ibex** is the JavaScript/TypeScript **runtime** used by Exact and Snapback —
a Hermes-based engine with web/Node/Bun-compatibility goals, in the spirit of
`node`, `bun`, or `deno`. It is a runtime, not an application framework: the
Exact project CLI and app layer live in the `exact` repo; this repo is just the
runtime and its embedded JS layer.

Ibex was extracted from the `exact` monorepo (see exact's LLP 0180) into its own
repository so it can be versioned, CI-tested across platforms, and depended on
by multiple consumers (Exact and Snapback) without each one vendoring the whole
monorepo.

## Architecture / subsystems

- **Rust crate (`exact-runtime`)** — the crate name is still `exact-runtime`
  during the transition; the repo/product is `ibex`. Exposes the host ABI and
  links the Hermes engine.
- **Hermes bindings (`src/engine/*.cc`)** — the C++ that drives Hermes: JS eval,
  the host-call bridge, and the platform shims (crypto, fs, process, net, http,
  dns). Compiled by `build.rs` via `cc`.
- **Host ABI (`src/host`)** — the Rust surface consumers link against:
  `install_host`, `Host`, and the C ABI functions. This is the contract.
- **Module loader + builtins (`src/module_loader`, `src/builtins`)** — module
  resolution and the `exact:*` / Node / Bun builtin modules.
- **Embedded JS runtime layer** — the builtin sources + the bundled runtime are
  generated from JS authoring in this repo (the generators under
  `packages/ibex-devtools`, the runtime JS under `packages/ibex-runtime-js`,
  and `modules.ts`) and committed as a snapshot under `vendored-generated/`.
- **Hermes artifacts** — prebuilt per platform under `linux/`, `ios/`,
  `tools/hermes/` (gitignored build outputs; produced by `scripts/build-hermes-*.sh`).

## Key invariants (not obvious from the code)

- **The default build is hermetic.** `cargo build` (and `--features openssl-crypto`)
  with no env flags MUST NOT require `bun` or `node_modules`: it uses the
  committed `vendored-generated/` artifacts. Native regeneration of those
  artifacts (running the JS generators with `bun`) is an explicit dev path gated
  behind `IBEX_REGENERATE_RUNTIME=1`. If the vendored artifacts go missing the
  build fails loudly rather than silently regenerating. @ref LLP 0086 review F7
- **The consumer contract is narrow and stable** (exact's LLP 0038): five C ABI
  functions (`ex_hermes_create`, `ex_hermes_destroy`, `ex_hermes_eval`,
  `ex_hermes_free_string`, `ex_hermes_set_host_call`) plus the Rust
  `host::{install_host, Host}` surface. Treat changes to these as semver-major.
- **Crypto is platform-dependent** (see [LLP 0001](./0001-target-platforms-and-ci-matrix.rfc.md)):
  Apple platforms use CommonCrypto/Security (no OpenSSL); Windows uses
  `crypto_windows.cc` with `EXACT_NO_OPENSSL`; Linux and Android have **no**
  platform backend and therefore REQUIRE the `openssl-crypto` feature for real
  hashing/HMAC/sign. The default (no-OpenSSL) profile on Linux only registers
  asymmetric crypto as throwing stubs.
- **Target-platform support is uneven** today: `build.rs` handles macOS, iOS,
  Linux, and Windows; Android and tvOS are not yet wired. LLP 0001 defines the
  intended platform matrix and tracks the gaps.
