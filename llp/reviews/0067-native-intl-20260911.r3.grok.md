## Summary

ResolveLocale in the supplied ES2020 negotiation source canonicalizes **string** Unicode option values (UTS 35 syntax, then canonical form) **before** locale-data membership. Unsupported options that are not members leave the already-selected requested value, including its `supportedExtensionAddition`. `hour12` is different: InitializeDateTimeFormat sets `opt.[[hc]]` to **null**, null is in the hc list, and a requested `hc` addition is therefore cleared even when a sibling `hourCycle` is also present.

The delta matches that:

- `numberingSystem`/`calendar` options are ASCII-lowercased before support lookup (`ARAB`/`BUDDHIST` → `arab`/`buddhist`).
- Retention of `ca`/`nu` compares the **selected** value to the requested extension, so `foobar` no longer strips `-u-ca-buddhist` / `-u-nu-arab`.
- `hour12.is_none()` is required to keep `hc`, so `hour12` clears a requested `hc` regardless of `hourCycle`.
- Effective `hour12` mapping still uses the locale default (`h11`/`h23` vs `h12`/`h24`), not the requested cycle.
- Explicit time zones reject any UTF-16 unit `> 0x7f` **before** ICU case folding, then `pop_back()` still drops only the NUL from `utf8_to_uchar`, so `utc` / `aMeRiCa/nEw_yOrK` remain ASCII-fold matches.
- NF/DTF constructors stay ordinary `function` + `new.target` callables. Public methods, the format getter, bound format, and Date/Number/BigInt locale methods are concise methods or arrows (nonconstructable) with names/lengths restored by `defineProperty` where needed.

The primitive-`newTarget.prototype` fallback is **not** fixed. The two ignored expected-correct tests remain ignored.

## Optional suggestions / inherited limitations

- **Coverage gap, not a logic bug.** The new DTF case (`intl_datetime.rs` around the `en-u-ca-buddhist-nu-arab-hc-h23` + `hour12:true` fixture) does not also pass `hourCycle`. `resolved_locale` still drops `hc` whenever `hour12` is `Some`, so a sibling `hourCycle:"h23"` or `"h11"` cannot resurrect the keyword. A combined assertion would lock that.
- **`hour_cycle_option` is now redundant for valid inputs.** After `locale_hour_cycle` is chosen from a valid `hourCycle` option or the extension, `hour_cycle_option.is_none_or(|value| value == locale_hour_cycle)` only extra-strips an invalid `hourCycle` that JavaScript `stringOption` already rejects. Harmless; same selected-vs-requested rule as `ca`/`nu` would suffice plus `hour12.is_none()`.
- **UTS 35 canonical form (aliases) is still not applied to options.** `uloc_toUnicodeLocaleType` is used on ICU calendar inventory entries (`gregorian` → `gregory`), not on the option string. `ISLAMICC` becomes `islamicc` and will not match `islamic-civil`. The commissioned change is ASCII lowercase of syntactically valid types, not alias replacement.
- **Time-zone compare after the ASCII gate is still ICU `u_strCaseCompare`.** For ASCII-only input vs ASCII IANA names that is equivalent to ASCII case-insensitivity. That is the intended Kelvin fix, not a switch to a hand-rolled ASCII fold.
- **Unchanged, documented limitations:** primitive `newTarget.prototype` fallback; `formatMatcher: "basic"` still shares ICU best-pattern; absent Intl constructors and Mac NumberFormat gaps; no full Intl/test262/2027 claim. Fresh production-artifact / exact-shim qualification before npm writes is pending release work, not a code defect in this delta.
