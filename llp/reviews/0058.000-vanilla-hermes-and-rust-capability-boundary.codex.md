### Verbatim review

The closure-based engine seam is feasible, but this revision does not yet establish that the zero-patch profile preserves the secure product contract.

1. **MATERIAL — Deputy and constrained-principal protections are silently changed, not preserved.** Under D3/D6, `Promise.resolve(x).then(deputy.readFor)` later invokes `readFor` with only the deputy’s lexical capability context. Patch 0008 currently includes the ungranted scheduler and denies; patch 0013 similarly preserves multi-principal constraints across Promise adoption and reactions. D5 may classify exporting that callback as delegation, but that is a weaker product contract, while §8.3 still promises that a dependency cannot reach root authority through a Promise, timer, or detached callback. **Why it matters:** the same scenario is simultaneously permitted by the architecture and forbidden by the acceptance gate. **Smallest disposition:** explicitly choose bearer/object-capability semantics or retained deputy denial. If choosing bearer semantics, define any export or handoff of an authority-closing function as delegation, qualify §8.3, and require accepted amendments to LLP 0013/0040/0039 as applicable. If retaining denial, require a Rust-mediated attenuated service/handle design or retain the patched profile for that tier. Add the exact detached-deputy Promise fixture.

2. **MATERIAL — Removing authority properties from `globalThis` is insufficient while the real global and intrinsics are shared and mutable.** A dependency can replace `Promise.prototype.then`, a constructor, or another shared helper and capture a privileged callback that closes over a module-bound operation. That is authority discovery through shared state, not deliberate handoff. Patches 0004–0006 currently provide compartment isolation and native lockdown; “ordinary upstream hardening where sufficient” is not a decided replacement contract. **Why it matters:** lexical authority is only private if shared machinery cannot interpose on its use. **Smallest disposition:** mandate a stock-public, pre-project integrity contract for the shared intrinsic/global graph and private loader machinery, with adversarial poisoning tests. If that contract cannot be met on vanilla Hermes, narrow the profile to one trust domain or retain isolation elsewhere.

3. **MATERIAL — Core product decisions remain explicitly unresolved.** D4 declares module-only authority access a compatibility decision, but §11.1 still asks whether it is acceptable; §11.4 leaves the initial threat population—general npm graphs versus authored modules—open; and M6 mandates deleting the patched profile while §11.5 reopens that choice. **Why it matters:** these choices determine the security claim, supported module formats, compatibility break, acceptance corpus, and fallback strategy. **Smallest disposition:** resolve §11.1 and §11.4 in this RFC and reconcile M6 with §11.5. The structured-evaluation and no-eval implementation choices may remain deferred because their owning-contract gates already fail closed.

4. **MATERIAL — The flip gate is not closed-world.** D2 and §8.2 quantify over “v1 operations,” while migration retains Ibex 1 paths and includes diagnostics, extensions, bootstrap bridges, and direct transports. R4 correctly says generated inventory and effect-path joins are necessary, but §8 does not require them. **Why it matters:** every listed gate could pass while an uncatalogued native or legacy effect path remains reachable in the secure artifact. **Smallest disposition:** add an artifact-wide, posture-specific gate proving that every reachable capability effect—legacy, native, extension, diagnostic, bootstrap, and platform entry included—is either absent/refused or joins exactly one Rust authorization path.

Non-blocking child-Spec obligations include defining raw JavaScript handoff as an untracked bearer transfer unless Rust mints a derived delegation, requiring possession-safe opaque handles rather than merely guess-resistant generation numbers, binding cached builtin namespaces per module context, and ensuring retained timer/async context is never installed as ambient callback authority. M3 should also state that unmigrated APIs are absent on `upstream-pinned`, or move its final global inventory after M4.

### Verbatim cluster review

## Findings

1. **MATERIAL — The engine/job-queue seam remains open.**  
   **Affected:** LLP 0058, LLP 0058.000, LLP 0058.000.000.  
   LLP 0058 still calls OQ1 “gating,” while the Spec provides no normative drive API or state machine. Its loop starts by taking a Rust task, so an already-queued Hermes microtask can run after a timer or callback; ordering among native completions and timers is unspecified; nested drives can execute another host task before the outer checkpoint; finite-work fairness is undefined; and teardown covers queued owner tasks but not pending Hermes jobs. The handoff is also non-transactional: the supplied `pump_one_timer` removes a timer before `enqueue`, and Spec completion transitions occur before owner-queue admission, so refusal can lose work or strand a promise. The capsule does not establish that the required checkpoint/control operations exist through the pinned Hermes public interface.  
   **Smallest disposition:** Define a normative driver state machine with pre-drive and post-task checkpoints, unified ready-task arbitration or explicitly unspecified cross-source ordering, reserve/commit/rollback handoff, nested-drive behavior, finite-work fairness, and closing behavior for both queues. Name the required public adapter operations and require a pin-bound stock-Hermes feasibility probe before this seam is accepted.

2. **MATERIAL — Fixed module bindings are not specified for the artifact shapes on which the design depends.**  
   **Affected:** LLP 0058, LLP 0058.000, LLP 0058.000.000.  
   The Spec permits a “bounded wrapper” but does not enumerate supported source, CommonJS, lowered ESM, prepared, and HBC ABIs. Extra factory arguments cannot give an already-compiled HBC body a lexical `fetch` if its bytecode performs a global lookup. Such an artifact must either be rebuilt under a binding-aware wrapper, fail compatibility, or regain an authority global. “Unsupported shapes refuse” is safe but leaves migration feasibility and the shipped application tier undecided.  
   **Smallest disposition:** Define the supported artifact matrix and one receipt-bound factory ABI: parameter names/positions, compile-time wrapping, HBC metadata/version binding, invocation, and mismatch refusal. Explicitly reject native/pre-existing shapes that cannot carry it. Demonstrate that construction and invocation use only stock public Hermes embedding interfaces.

3. **MATERIAL — The vanilla threat population is internally contradictory.**  
   **Affected:** LLP 0058.000, LLP 0058.000.000.  
   D8 limits vanilla to one trust domain of “authored and cooperative modules,” while §§3.1 and 8.3 require containment of a dependency attempting authority discovery. LLP 0013’s supply-chain population is expressly malicious or compromised packages; such a package is not cooperative and is mutually hostile to the application. Consequently, “supply-chain containment” is either vacuous in vanilla or is a hostile-module claim the RFC says belongs elsewhere. This changes which product graphs may safely select vanilla.  
   **Smallest disposition:** State the adversary precisely. Either include arbitrary compromised JavaScript modules for authority non-discovery while expressly excluding shared-object integrity, DoS, and process isolation, or exclude them and remove the supply-chain claim plus refuse such graphs. Define what additional guarantee distinguishes the hostile-module tier.

4. **MATERIAL — Stock-public lockdown is an assertion, not yet a deterministic contract.**  
   **Affected:** LLP 0058.000, LLP 0058.000.000.  
   “Freeze the required graph” provides neither a closed root set nor descriptor traversal, treatment of accessors/proxies/host exotics, mutable exceptions, or failure rule. Named poisoning fixtures sample the graph but cannot prove closure. Omitting one mutable intrinsic can expose a privileged callback; traversing an exotic object through an observable trap can itself violate the no-project-code bootstrap window. The current native patch has an explicit descriptor-only deep-freeze contract, but no equivalent public construction is supplied here.  
   **Smallest disposition:** Specify the integrity root inventory, descriptor/prototype traversal, handling of exotic or unfreezable nodes, and exact fail-closed postcondition. Generate mutation tests from that inventory and provide pin-specific evidence that the algorithm and root-surface cleanup work on stock Hermes.

5. **MATERIAL — LLP 0013 and LLP 0040 are not cleanly assigned to tiers or amendments.**  
   **Affected:** LLP 0058.000, LLP 0058.000.000.  
   LLP 0040 mandates a live constrained-principal carrier for every capability class and says possession of a native handle alone does not authorize exercise. The new Spec instead makes possession sufficient and carries no caller/scheduler context. Yet M4 includes native extensions in vanilla, while the patch-retirement table treats patch 0013 as replaced; the general warning not to weaken LLP 0040 does not resolve which behavior ships. Likewise, an LLP 0013 policy selecting `deputyClasses`, and its frame-accurate audit claim, cannot silently become bearer-only.  
   **Smallest disposition:** Add an explicit feature/policy-to-profile matrix. Until accepted amendments name the replaced deputy, constrained-principal, and audit contracts, vanilla must reject nonempty LLP 0040 extension registries and policies requiring stack intersection; those remain on the patched profile. Make accepted amendments a flip gate.

6. **MATERIAL — The new postures are not mapped to Accepted LLP 0039.**  
   **Affected:** LLP 0058.000, LLP 0058.000.000.  
   `WholeRuntimeCompatibility` is not identified as either LLP 0039’s ambient standalone path or a different enforced posture. Secure development is omitted, and the standalone artifact’s ambient default plus monotonic CapSec selector is not mapped to an engine tier. A standalone containing third-party dependencies could therefore switch its “secure” branch to vanilla even though this RFC assigns unvetted graphs to the patched/isolated tier.  
   **Smallest disposition:** Provide a posture table mapping every LLP 0039 entry point and selector to enforcement state, engine receipt, eligible graph, and downgrade rule. Preserve the secure-default CLI and the standalone ambient/CapSec selector contract explicitly.

7. **MATERIAL — The boundary conflicts with LLP 0059.000.**  
   **Affected:** LLP 0058.000, LLP 0058.000.000.  
   LLP 0059.000 specifies generic `hostCallInline(op, …)` and `hostCallAsync(op, …)` lanes, whereas this Spec forbids JavaScript-selected operation IDs and requires fixed-operation closures. A literal generic surface can bypass operation-specific binding and attenuation. LLP 0059.000 also declares timers pure and ungated, while these documents call actor-retaining timers capability-bearing, `ContextRequired`, and module-bound. Following one contract can recreate stack-derived global timers; following the other can incorrectly grant-gate timers.  
   **Smallest disposition:** Amend LLP 0059.000 to state that its generic dispatcher is Rust-internal behind fixed native closures. Make grant classification and provenance orthogonal: timers remain ungated but actor-retaining schedule/clear/ref operations are `ContextRequired` and module-bound; `queueMicrotask` may remain shared.

8. **MATERIAL — Policy, revocation, async completion, and lifetime semantics are not linearized.**  
   **Affected:** LLP 0058.000.000.  
   The policy rule says an old generation is validated “under the owning policy’s rules or” requires a new binding—two observably different security contracts. No linearization point relates revocation to validation, transport start, staged effects, timer readiness, completion enqueue, or owner delivery. For example, completion can validate, queue, then succeed after revocation because owner delivery revalidates only runtime and callback state. The Spec also lacks a producer-safe completion-token schema, complete ownership rules for callback/resource roots, and a terminal disposition when queue admission fails; an admitted promise can hang or records can leak.  
   **Smallest disposition:** Define one policy-generation rule and a transition table covering admission, each effect stage, revocation/cancellation, producer completion, queue reservation, owner delivery, and teardown. Specify which side wins each race, ensure every admitted operation settles or is destroyed with its runtime, revalidate all security-relevant records at the chosen delivery point, and define an opaque producer-safe completion lease with exact root-release ownership.

9. **MATERIAL — User-code-capable coercion creates a validation gap.**  
   **Affected:** LLP 0058.000.000.  
   `invoke_inline` says it never invokes project code, but §5.1 permits Web-required property reads, getters, proxies, and coercions after validation. Such code can revoke the binding or begin teardown before authorization/effect, leaving the implementation to proceed from a stale validation. Holding policy/table guards across the getter would instead create reentrancy and deadlock hazards.  
   **Smallest disposition:** Mark conversion plans as primitive-only or user-code-capable. Validate before initial access, run observable coercion without security/drive guards, then fully revalidate and atomically authorize/admit before effect. Clarify that the Rust body does not call project code even though adapter coercion sometimes may.

10. **MATERIAL — The closed-world gate has no completeness oracle or format.**  
    **Affected:** LLP 0058.000, LLP 0058.000.000.  
    The RFC expressly assigns the child Spec an inventory-format obligation, but the Spec only repeats that every path must be inventoried. A hand-maintained list cannot prove that an omitted legacy global, extension hook, platform import, diagnostic bridge, or direct transport is missing; therefore `upstream-pinned` has no deterministic graduation test despite the otherwise-correct non-selectability rule.  
    **Smallest disposition:** Define the inventory schema and authoritative inputs: artifact entry roots, generated operation catalog, native/platform effect sinks, extension/diagnostic registries, legacy spellings, and a per-sink absent/refused/operation-join record. Make unregistered roots or sinks a build failure on every shipped artifact.

## Strengths

The set makes several strong decisions clearly: missing provenance fails closed; authority is carried by private fixed-operation tokens rather than guess-resistant scalars; runtime and slot generations are explicit; module namespace caching includes the full context identity; bearer delegation is admitted honestly; safe refusal construction and owner-thread engine access are normative; the patched tier is retained; and `upstream-pinned` is expressly an oracle rather than migration evidence.

## Non-blocking obligations

- **NON-BLOCKING — LLP 0052 is precedent, not the governing in-process handle contract.**  
  **Affected:** LLP 0058.000, LLP 0058.000.000.  
  The supplied excerpt governs durable, JS-dead, cross-process authority envelopes and explicitly does not re-own the general policy model. Relabel it as an analogy for possession/lifetime and cite the actual in-process typed-handle owner—or state that this Spec establishes the new contract itself.

- **NON-BLOCKING — Bound derivation depth needs a cost rule.**  
  **Affected:** LLP 0058.000.000.  
  Unbounded ancestor traversal conflicts with bounded inline execution. Cap derivation depth, flatten immutable ancestry, or precompute a bounded revocation vector.

- **NON-BLOCKING — Make oracle-only selection mechanical.**  
  **Affected:** LLP 0058.000, LLP 0058.000.000.  
  The decision is correct; add negative packaging and product-selector tests proving the non-secure `upstream-pinned` receipt cannot enter a secure artifact before all gates pass.
