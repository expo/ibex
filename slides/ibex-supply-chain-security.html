the attack classibex · 04 / 16
why hasn't this been fixed?

process flags can't see packages

  • Process-level permissions — Node's permission model, Deno's flags — draw one boundary around all of your code. Your app needs the filesystem and the network, so the flags are on. The malicious dependency runs inside that boundary, with everything you enabled.
  • Scanners and advisories catch known-bad versions after publication, after installation, often after exfiltration. Detection is necessary. It is not containment.
  • Lockfiles, pinning, provenance prove you got the bytes you asked for. They say nothing about what those bytes are allowed to do.

The unit of compromise is the package.
The unit of enforcement must be the package.

the design · mechanism 3ibex · 09 / 16
frame-derived attribution

identity is read from the bytecode,
not from a variable

executing frame → CodeBlock → Domain → package principal → policy check  // engine truth. JS cannot set it.
  • The forgeable version is gone. The old thread-local module id — settable by one line of user code — is removed, along with the global grant function. There is nothing left to impersonate with.
  • Deferred attacks attribute to their author. A stored callback, a patched method, a promise job scheduled for later: when it finally runs, its frames still belong to the package that wrote it. Same async path as the app, same trusted deputies — different answer at the boundary.
  • Deputies stay transparent. The runtime's own fs / fetch / process layers carry a reserved runtime principal the frame walk skips — checks land on the real caller, not the plumbing.

llp 0014 · import-site grants

nobody maintains the policy file

// app.js — first-party code is the only grant channel import img from "image-lib" with { grants: "fs:read:/app/images, fs:write:/app/images", }; import pad from "left-pad"; // no attributes → empty grant set. contained.

Generated, committed, drift-checked. The build compiles every import-site grant into one policy artifact — checked in like a lockfile. Every reachable package appears, granted or empty. Every grant carries provenance: the file:line that issued it.

Grants garbage-collect. Delete the import and the authority disappears from the regenerated artifact. CI fails on drift and reports expansions loudly — new authority shows up in the PR diff, next to the import that caused it.

Tools that infer policy from what code does rubber-stamp the compromised version's new behavior. Ibex grants only what root code declares — so the hijacked release that suddenly wants the network is denied until a human widens their own import site, in their own reviewed diff.

the policy · delegationibex · 12 / 16
authority flows like data — on purpose

capabilities are objects you can hand over, narrow, and kill

// image-lib holds fs for /app/images — and delegates a slice const codec = require("fast-codec"); codec.decode(buf, fsHandle.scoped("cache/")); // codec has NO ambient fs. it can use // exactly this handle, exactly this far fsHandle.revoke(); // every handle derived from it // dies with it, fail-closed
  • Possession, not identity. A passed handle works within its grant — delegation between cooperating packages is a feature, not a hole. Frame attribution still writes the audit trail: codec wrote, via image-lib's grant.
  • Ambient fallback, bounded. Packages can request; only the app grants. Effective authority intersects down every dependency edge — a compromised intermediate can never delegate more than it was given.
  • Deputy hardening, opt-in. For the scary classes — fs:write, process:spawn — stack-intersection requires every principal on the stack to hold the grant.

the honest partibex · 14 / 16
threat model, stated out loud

what we refuse to claim

  • Deputies are what libraries are. An API that does I/O for its callers acts with its own authority — by design. We bound what exists to be misused, and offer stack-intersection where it matters; we don't pretend the pattern away.
  • Objects carry authority. A package may deliberately hand its granted handle to another. Endowment policy and attenuation bound what can be passed; the passing itself is the delegation model working.
  • Engine bugs bypass everything. Memory-safety escapes and side channels are below this layer. Genuinely hostile code still gets what it always got: its own isolated runtime instance.

The honest name is supply-chain integrity, not sandbox.
Security people can smell the difference. So can we.
