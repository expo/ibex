# Archived old-pin/new-pin dual-produce comparison

**Status:** Complete
**Severity:** P3
**Systems:** Build, CI
**Author:** Claude (Fable 5), directed by Charlie Cheever
**Date:** 2026-07-17
**Related:** LLP 0028 §1
**Depends-on:** oxc-toolchain-pin-rotation

CI dual-produces old-pin/new-pin artifacts for the corpus and compares
semantic metadata, source maps, and real-Hermes behavior, without
executing both in production. Old-pin side comes from the archived
producer binary built at the pre-bump commit (one workspace cannot
build both lockfiles). Precommit the semantic projection and
allowed-difference set in this issue before running.

**Done when:** content-addressed report archived; projection was
precommitted; discrepancies dispositioned or fixed.

## Precommitted comparison contract

This contract was recorded before either producer was run for the archived
report. The old side is the `module_runner_spike` example built from commit
`9329a9123a10e379d6253afb6a90a33de5de928e` with its checked-in Rust 1.93.1
toolchain and lockfile. The new side is the same example built from the
post-rotation worktree with Rust 1.97.0 and the canonical transform
configuration. Both sides receive byte-identical copies of
`tests/fixtures/module-runner-spike/manifest.json` and its `sources/` tree.

The report uses comparison schema
`ibex/oxc-old-new-dual-produce-report/1`. Its semantic projection is, in
manifest order:

- bundle `schema` and `manifestSchema`;
- fixture `id`, `entry`, `expected`, and ordered `tags`;
- module `fixtureId`, `sourceName`, `dialect`, `sourceIntegrity`, ordered
  `staticEdges`, ordered `dynamicEdges`, ordered `exportDescriptors`,
  `hasTopLevelAwait`, and ordered `hermesCompatPasses`.

That projection must be byte-identical under canonical JSON. It deliberately
excludes producer identity and generated bytes: those are compared and
reported separately, not mistaken for module semantics.

Every source map is decoded before comparison. The report records its full
decoded segment projection and requires on each side:

1. version 3, the expected factory filename, one source named by the module,
   byte-identical embedded source content, no out-of-range original location,
   and `x_ibex_composed: true`;
2. monotonically ordered generated locations and at least one mapped segment
   for each non-empty map;
3. every manifest-declared source-line oracle (currently the throwing
   source-map fixture) resolves from the generated throw site to the declared
   original line through Node's `SourceMap` consumer.

The map metadata, raw mappings, decoded segments, factory source, and their
digests are compared module by module and all differences are enumerated.
The only pre-authorized differences are:

- bundle/module `transformFingerprint`, which must change from the reviewed
  old identity to the reviewed new canonical-config identity;
- generated factory spelling/formatting; and
- source-map mapping/segment changes caused by that generated layout or by
  improved Oxc mapping precision, provided every invariant and source-line
  oracle above passes.

No semantic-projection difference, missing mapping, invalid mapping, source
identity/content difference, source-line-oracle difference, producer failure,
or real-Hermes behavior difference is allowed. Both complete bundles are run
independently through the real Hermes shell; all manifest expectations must
pass on both sides. The old and new artifacts are never both evaluated by a
production process.

The report binds the old commit, both toolchain/pin projections, manifest and
source-tree digests, producer binary digests, complete artifact-bundle
digests, Hermes binary digest, comparison results, and the contract above.
Its filename is the lowercase hex SHA-256 of the canonical report bytes.

## Execution finding and disposition

The first execution of the precommitted contract found one pre-existing defect
in the immutable old producer, before any new-side result was accepted:
`hermes-for-of-capture/entry.js` generated line 16 mapped to original line 8,
but the embedded source has only 7 lines. The old and initially rotated
producers emitted the same invalid segment. This means the original contract
is **not** retrospectively declared satisfied on the old side and the allowed
difference set above is unchanged.

The current producer fixes the defect by clamping lines introduced by a
handwritten statement expansion to that statement's final real source line.
The archived report and reproducible CI gate may disposition exactly this one
old-side defect only when all of the following remain true:

- the old defect identity and coordinates match the row above exactly;
- the new side has zero source-map invariant defects;
- the semantic projection is identical;
- every fixture passes independently on the same real Hermes binary; and
- no other unprecommitted difference class appears.

The report status for that outcome is
`pass-with-dispositioned-old-baseline-defect`, and its contract outcome records
that the original old-side map invariant failed. Any changed or additional
old defect, any new defect, or any semantic or behavior difference remains a
hard failure.

## Result

The reproducible comparison and CI job are landed. The archived report is
`llp/evidence/0028-oxc-dual-produce-d196aa522d0263f3280bbde1411892e85ef483f04ef42a15f8c1f3bd36cab1ba.json`;
its filename matches the SHA-256 of its bytes. The report proves:

- byte-identical canonical semantic projections;
- 12/12 fixtures passing independently on real Hermes for both producers;
- zero generated-factory differences;
- the exact one-row old malformed-map baseline and zero new map defects; and
- 12 enumerated source-map precision/layout differences, all within the
  precommitted generated-layout class.

The current producer regression test pins the synthetic-line clamp, the
canonical artifact was regenerated, and `module-loader-baselines.yml` rebuilds
the old producer in a detached worktree and uploads a fresh content-addressed
report.
