# LLP 0068.002: Adopting the consumer patches upstream

**Type:** Plan
**Status:** Active
**Systems:** Rust Stdlib, Host ABI, CapSec, Build, Consumer Integration
**Author:** Charlie Cheever / Codex
**Date:** 2026-10-13
**Revised:** 2026-10-15 (Windows render HTTP, physical iPhone images and bounded iPad network/storage evidence; rollout gates remain separate)
**Accepted:** Charlie Cheever, 2026-10-13, by directing implementation of these three documents.
**Related:** LLP 0068; LLP 0068.000; LLP 0068.001; LLP 0067; LLP 0069; LLP 0071
**Implementer:** Codex, coordinating this commission from 2026-10-13

## Summary

Give Ibex a supported home for the reusable changes Exact currently carries,
then remove each corresponding consumer patch only after Exact runs against
the replacement. Keep application scheduling, policy and integration in Exact.
The unit of completion is an upstream implementation plus a verified consumer
adoption, not an upstream commit alone.

Charlie commissioned these three drafts, one approach review by GPT-6 Astra
at max and Grok 4.7 at xhigh, and the accompanying maintenance work on
2026-10-13. This plan records the larger adoption sequence; publishing a draft
does not establish that its proposed APIs have been implemented or accepted.

## 1. Baseline and consumers

The inventory is Exact commit
[`075b946254a2cbfd6144b762b41727c5716eb544`](https://github.com/ccheever/exact2/blob/075b946254a2cbfd6144b762b41727c5716eb544/vendor/ibex/EXACT-PATCHES.md),
whose ledger identifies its Ibex base as `7f77c82`. The comparison here is
against Ibex `3c7a17a`. Reconcile any intervening changes before implementing a
row; the ledger is evidence, not a patch file to replay over live work.

Exact uses three boundaries: the engine-free Rust library, JSI bindings in a
caller-owned lean Hermes runtime, and the compiler/VM bundle resolver. Its
runner owns request scheduling, application clocks, cancellation policy and
budgets. Those responsibilities remain there (LLP 0068).

Snapback 4's Rust data engine does not embed Ibex. Exact's
[native Snapback adapter](https://github.com/ccheever/exact2/blob/075b946254a2cbfd6144b762b41727c5716eb544/snapback4/src/lib.rs)
uses Ibex's storage authority and passes HTTP exchanges to Exact's executor.
The first Snapback evidence is this existing integration: reopen an offline
partition, retain queued writes across restart, reconnect and synchronize,
and change accounts without crossing partitions. The implementation inventory
found that Snapback 4's media/asset API is not built. Cancellation of HTTP
uploads and image publication is therefore qualified through Exact's existing
executor and storage adapter; this is not evidence for a Snapback asset API.
No change to Snapback's data engine or Node action runtime is needed for this
plan. Adding a new Snapback media feature is a separate consumer task.

### B. Upstream bounded storage primitives

Start with the bounded opened-file reader and directory-result accounting
(10/12), with consumer-selected limits. Then migrate documents (4/5 and the
Windows fix) after resolving grammar ownership. Add codec and operation
lifetime support (9/11) together: an isolated codec port that loses Exact's
commit gate is not a completed slice. LLP 0068.001 defines the semantic unit.

### C. Upstream networking

Move the portable production transport selection and typed errors first
(3/6). Extract the shared redirect/grant logic and establish deadline semantics
with deterministic tests (7/13), then the Apple asynchronous transport and its
physical resource-retirement rules. Keep the bounded blocking adapter for
portable consumers while qualifying further transports separately. LLP
0068.000 owns this interface; Exact's lane policy and numerical budgets remain
in its own design.

### D. Refresh and retire in the consumer

For each coherent slice, compare the old upstream tree, Exact's carried tree,
and the new upstream tree. Apply the remaining consumer delta deliberately.
Preserve unrelated edits, grants and resolver security. Record the new source
revision and every retained patch in Exact's ledger, then run the relevant
Exact consumers. Remove a patch row only with that evidence, or mark the
replacement explicitly if a small consumer adapter remains.

A patch is not retired merely because files become textually identical: its
consumer-visible behavior must still be exercised. Conversely, an Exact-only
stub or scheduling adapter can remain without making the adoption incomplete.

## 4. Evidence and acceptance

Keep tests beside the implementation or existing consumer tests. Add no new
blocking check framework. Each implementation commit carries its governing
LLP update, focused regressions, the workspace clippy checks and `./ref-check`
required by AGENTS.md.

Qualify the three doors independently: engine-free Rust, borrowed bindings
linked to the lean VM, and the owning runtime. Preserve hardening before
application code and caller-owned clocks. Test denial as absence of provider
or network work, rather than just checking an error string.

Consumer evidence names the Ibex source revision, Exact revision, engine
bundle identities, target and command. Run the affected Exact data executor,
storage and Snapback integration scenarios; distinguish platform compilation
from a running native test. Cross-platform semantics should use the same
fixtures where practical, with actual execution recorded per target.

An Android release is complete only after its immutable artifact and
attestation have been verified, the authenticated resolver pin is updated,
and installation plus offline consumption succeed. A locally built archive
or a workflow change alone is preparation, not publication.

## 5. Open implementation choices

- Grant sharing uses a typed document-provider handoff and parity fixtures.
  Ibex retains its independent grammar; Exact retains its application-only
  vocabulary. Neither repository acquires a dependency in the wrong direction.
- `Documents`, `DocumentLease`, `ImageService`, `ImageWork`, and `WorkHandle`
  implement the storage boundary in 0068.001; the provider receives admitted
  logical identities and retained handles, never ambient filesystem authority.
- Portable async transports are a measured follow-up. A bounded blocking
  adapter must label its worker cost honestly.
- Runtime-setup measurements determine whether a structural optimization
  deserves another RFC. No snapshot implementation is assumed by this plan.

The coordinator records each completed slice in its existing issue/consumer
ledger and this plan's revised evidence. Charlie authorized implementation of
all three documents on 2026-10-13. Their required implementation and adoption
evidence is complete in §6, so all three now have Active status.

Exact's ImageIO provider now charges component depth, aligned rows and decoder
workspace, reserves 25% scratch headroom, and refuses the prior oversized

slots until actual native return and preserve old targets after abandonment.

opaque, and no hard allocator, RSS or native-call duration bound is claimed.
LLP 0068.001 links the full consumer measurement record. Snapback's persistence and
reconnection tests do not establish an unimplemented asset/media API.
