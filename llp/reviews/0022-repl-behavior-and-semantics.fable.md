# Independent Design Review — LLP 0022: REPL Behavior and Semantics (rev b3332765d1c1, round 1)

## 1. Overall assessment

This is a genuinely good spec attacking a real, verified problem. The motivating diagnosis is accurate and I reproduced it empirically: the armed runtime closes native cwd disclosure (`src/engine/hermes_runtime.cc:1653-1656` returns `undefined` when armed), the JS process facade falls back to `/` (`src/builtins/process.js:69-82`), `fs` eagerly absolutizes against it (`src/builtins/fs.js:514,570-592`), and the armed host then joins relative paths against the *Rust process* cwd and prefix-matches bindings (`src/host/mod.rs:288-298`). Running the armed binary from a temp project containing `README.md`, `fs.readFileSync("README.md")` fails and `process.cwd()` returns `/`. The three-concepts analysis (host startup directory / armed logical binding / JS-visible cwd) is the right frame, and the virtual `/project` namespace is the right resolution — it is essentially the WASI-preopen move, well precedented in capability systems, and it keeps LLP 0021's disclosure posture intact while making relative paths usable.

The document's second major contribution — the §10 REPL-affordance parity rule — is its best idea and is well earned: I confirmed the shipped `.env` command leaks the raw host environment around the armed gate (`src/bin/ibex/repl/mod.rs:966-971`; a marker variable set for the test appears in `.env` output of a piped armed session), `.load` is a raw host read plus bare global eval (`src/bin/ibex/engine/hermes.rs:1145-1159` via `run_file_immediate:1599-1604`), and tab completion evaluates the base expression via `Function('return (' + expr + ')')()` (`repl/mod.rs:296-297`), so accessor getters run on Tab. Every load-bearing "current implementation" claim I checked is true, including the TLA statement wrapper dropping `let`/`const` (`repl/mod.rs:1174-1186`), the string-level `import(` → `globalThis['import'](` rewrite that also rewrites string literals (`repl/mod.rs:862`), and the import path that prints `[capability granted: …]` while calling the legacy `Exact.setModuleCapabilities` (`repl/mod.rs:818-836`) — the misleading acknowledgment §8 prohibits. The spec also correctly codifies behavior that already exists where it is right (bounded EOF drain, `hermes.rs:204-210,1554-1591`).

That said, the document is not yet a finished normative contract. It contains one normative rule that is simply wrong for valid JavaScript (`.5 + 1` becomes a dot-command error under §11 as written), several places where the stated rule is not well-defined enough to implement or test deterministically (per-input JS/TS decision, plain-protocol input grouping, prompt `with{}` attribute semantics), one safety gap inside its own threat model (terminal injection through the error channel it doesn't cover), a mount-table decision (`/home` = machine-global runtime cache) that quietly creates a cross-project disclosure/poisoning surface and a host-path spelling collision, and a completion guarantee whose stated mechanism cannot deliver the stated property without engine support the doc doesn't call out. All of these are fixable by revision rather than redesign, but together they clear the bar for material concerns.

## 2. Strengths

- **Verified, honest motivation** (§Motivation): every cited divergence exists in the code as described — `.env` (`repl/mod.rs:966-971`), `.load` (`hermes.rs:1145-1159`), getter-invoking completion (`repl/mod.rs:283-297`). The doc reads like it was written against the code, because it was.
- **The §10 parity rule** — "no REPL affordance may read or disclose host state the armed model closes to the session's JavaScript" — is a durable invariant, not a bug list. It generalizes the `.env` withdrawal and gives future dot-commands a decision procedure. Criterion 14 (marker-variable, exercised end-to-end) is a strong adversarial test shape.
- **The mode triad** (§2): interactive / program / plain-protocol, with plain protocol as the deterministic, scriptable projection, is exactly right for a repo whose Consequences section honestly admits there is no PTY harness yet. Program mode matches Node/Bun piped-stdin behavior; keeping `ibex repl` as the explicit REPL surface for automation is clean.
- **Correct security spine** (§1, §3, §8, §10): armed posture unchanged at the prompt (confirmed: the REPL path goes through `Runtime::from_cli` → `build_default_armed_host`, `src/bin/ibex/runtime.rs:1040-1071,1641-1996`, and inspector flags are refused pre-arming at `runtime.rs:1998-2026`); no implicit rc files (criterion 16 is a nice decoy test); imports through the ordinary loader with package attribution; typed-decision path for `.load` and `.save`-class commands.
- **Decision quality of the contested defaults**: sloppy-mode prompt with Node/Bun/Deno precedent and a strict toggle deferred to open question 8; second-Ctrl+C session exit rather than a wedged prompt, with Hermes interruptability honestly parked in open question 6; POSIX-shaped virtual paths on Windows; withdrawal of `.env`. Each is argued, not asserted, and the compatibility-priority ladder (§Compatibility priorities) makes future conflicts decidable.
- **Acceptance criteria are unusually adversarial and specific** (criteria 3, 12, 14, 15, 16, 21, 24): symlink-escape distinct errors, instrumented getters on the base chain, title-change observation for escape sequences, vendored-vs-source builtin parity (24) — the last one closing a real hermetic-build trap.
- **Implementation guidance names the actual code to retire** — the hand-rolled bracket scanner (`repl/mod.rs:486-563`), string-matched import rewriting, the `<eval>` source name (`hermes.rs:1517,1524`), the chmod-after-the-fact history trap, the panic-hook terminal restore — and correctly identifies that file-exec already reads `process.exitCode` while the REPL does not (`main.rs:1325-1327` vs `main.rs:1333-1367`).

## 3. Concerns

**1. The `/home` mount exposes the machine-global runtime cache to every session and collides with the commonest host-path spelling.** — **Material (safety + decision quality).**
Evidence: §3 mounts `/home` ← logical root `home`. In the default armed snapshot that binding is the machine-global Ibex cache — `~/Library/Caches/Ibex` / `~/.cache/ibex` (`src/bin/ibex/runtime.rs:1918-1945`, `runtime_cache_dir` at `runtime.rs:3445-3461`), which holds compiled bundle artifacts for *all* projects and is not in LLP 0021's protected-object set ("exactly armed policy, engine binary, package graph, and registry"). Making it JS-addressable in every root session (a) lets a session in project A read (and, if ambient root admits `fs:write` there, overwrite) project B's cached bundles — cached artifacts are later-executed code, so writes are a cross-session/cross-project poisoning channel the spec neither denies nor acknowledges; (b) shadows the most common Linux host-home prefix: a host-absolute typo like `/home/user/x` resolves *inside* the cache mount and yields an ordinary in-mount `ENOENT`, defeating §3's own promise that accidental host paths produce a distinct outside-mount error (criterion 3 tests `/etc/passwd` but not `/home/...`).
Resolution: either drop the cache binding from the JS-visible namespace (keep it runtime-internal for the loader), or rename the mount (e.g. `/cache` or `/state`) *and* specify the authority posture over it (at minimum: deny write to executable cache artifacts, or extend the protected-object set), and add a `/home/<user>`-shaped fixture to criterion 3.

**2. Terminal-injection escaping does not cover the error channel.** — **Material (safety).**
Evidence: §9 ¶3 scopes the escaping obligation to "the REPL's own value display" when "inspection renders a string"; §9's error paragraphs require name/message/stack and disclosure hygiene but no escaping; criterion 15 tests only "a displayed string." Error messages, stacks, async-rejection reports (§9 ¶6 — explicitly including *package-attributed* text), symbol descriptions, function/class names, and property keys are attacker-controlled text the REPL itself renders. `throw new Error("\x1b]0;pwned\x07")` injects via stderr under the spec as written. Note also the current inspector quotes strings with `JSON.stringify` (`packages/ibex-runtime-js/src/inspect/inspect.ts:130`), which escapes ESC (C0) but *not* single-byte C1 CSI/OSC introducers (0x9B/0x9D) — the spec correctly names CSI/OSC, but only for values.
Resolution: restate the obligation as: all REPL-authored output derived from runtime values — value display, error name/message/stack rendering, async reports, completion candidates and hints — is terminal-safe, including C1 introducers; extend criterion 15 with a thrown-error and an async-rejection fixture.

**3. §11's dot-command rule mis-handles valid JavaScript (`.5 + 1`), and its premise is false.** — **Material (correctness of a normative rule).**
Evidence: §11 opens "REPL dot commands occupy a namespace that cannot be produced by JavaScript grammar at the start of a fresh input" and mandates that any `.`-leading line matching no command "is an error naming `.help`; it is never evaluated as JavaScript." But `.5` *is* JavaScript grammar at the start of a fresh input (`.5 + 1` === 1.5); Node's REPL explicitly exempts number-parsing lines for this reason. The current implementation has the same bug (`repl/mod.rs:802`), so the spec would freeze it.
Resolution: define command syntax as `.` followed by an ASCII letter (or: not followed by a digit), state that `.`-digit inputs are expressions, and correct the preamble sentence.

**4. The per-input JS/TS decision procedure is not well-defined.** — **Material (correctness/determinism).**
Evidence: §5 says language is "decided per input by content, using the same transform pipeline that file execution uses" and that TS inputs behave "exactly as a file with the same text would be." But the file pipeline decides by *extension*, not content (`needs_transpile`, LLP 0004 §Loading), so "a file with the same text" is ill-defined; JS and TS grammars overlap with divergent semantics (`foo<Bar>(baz)` is a comparison chain in JS, a stripped generic call in TS), so "by content" has genuine ambiguity; and "the same transform pipeline" is itself ambiguous because file execution has two pipelines (the build-time AST authority vs. the in-process swc path — LLP 0019's two tiers). Acceptance criteria 8–9 cannot be written deterministically until this is pinned.
Resolution: pin the tiebreak (e.g. "prompt input is parsed as TypeScript always, as Deno does; known JS/TS divergences are enumerated" — or "JS parse first, TS on failure") and name the pipeline tier (the in-process module-loader transform) the prompt shares.

**5. Prompt `with { … }` attribute semantics don't map onto LLP 0014's grant channel; criterion 17's "equivalent file-based import site" is ill-defined.** — **Material (coherence).**
Evidence: §8 says a prompt attribute "can select or attenuate within the armed ceiling" and is "subject to exactly the rules that govern the same attribute at an import site in a file." But under LLP 0014 + LLP 0021, file import-site grants are *build-time authored source* compiled one-way into the immutable armed snapshot; the bundler strips grant attributes before the engine sees them (LLP 0014 §The grant channel), and nothing is consulted after arming (WP4). There is no runtime phase for an import attribute to "select" anything, unless the spec means it maps onto the typed dynamic-grant stratum (which is closed by default — empty ceilings). The two readings (inert-with-honest-report vs. dynamic-grant request within ceiling) have different observable behavior.
Resolution: one paragraph stating the mechanism: e.g. "at the prompt, an authority attribute is not consulted for authority at all; it is reported as inert against the armed snapshot" — or — "it is translated to a typed dynamic session-grant request under stratum 12 and its ceiling," and rewrite criterion 17 against that mechanism.

**6. §13's completion guarantee is not implementable by its own stated mechanism.** — **Material (feasibility).**
Evidence: §13 requires that property discovery "walks own-property names and descriptors without performing property reads" and "when a step in the chain is an accessor or a proxy, completion stops … rather than executing user code." But `Object.getOwnPropertyNames`, `getOwnPropertyDescriptor`, and `getPrototypeOf` on a Proxy *run trap code*; pure JavaScript cannot detect a proxy without invoking a trap. Delivering "no user code runs" requires an engine-level primitive (proxy detection / trap-bypassing own-key enumeration) in the patched Hermes, which the doc's implementation guidance ("descriptor-walking strategy") never calls out, and criterion 12's "creates no filesystem or network evidence" would be violated by an instrumented `ownKeys` trap under a naive descriptor walk.
Resolution: either require a named engine primitive (e.g. a native `isProxy`/safe-own-keys host function in the patched Hermes) in §13/implementation guidance, or weaken the guarantee to "no accessor invocation; introspection traps may observe the walk" — and make criterion 12 match.

**7. Plain-protocol mode leaves input grouping, EOF-with-incomplete-input, and transcript-determinism scope unspecified.** — **Material (testability of the spec's own strategy).**
Evidence: §2 defines plain protocol as "full REPL semantics … no line editing" with byte-deterministic output, but never says how multiline inputs are delimited without a line editor (presumably §5 completeness applies — unstated), nor what happens to a trailing incomplete input at EOF (error? silently dropped?), nor which streams the determinism claim covers. Empirically, a piped `ibex repl` today emits arming diagnostics ("capsec readiness: …") before the banner; the spec doesn't say whether startup diagnostics belong to stderr and are excluded from transcript fixtures. Criterion 18 is unimplementable as a byte-level test until these are pinned.
Resolution: state that §5 completeness governs input grouping in all REPL modes; define EOF-with-pending-continuation behavior; scope determinism to stdout (or stdout+stderr) explicitly and place arming diagnostics on stderr.

**8. The no-host-path-disclosure invariant is under-enumerated: `process.execPath`, `process.argv[0]`, `os.homedir()`, `os.tmpdir()`, `module.paths`, and runtime-bundle stack frames.** — **Material (completeness of a headline property).**
Evidence: §1/§3/§9 build the "JavaScript does not learn host paths" story, and criteria 2/13 test cwd outputs, errors, banner, and history — but the CLI bootstrap injects the binary's host path as `__exactExecPath`/`process.execPath` (`runtime.rs:1108-1137`), `os.homedir`/`os.tmpdir` are host-path-bearing builtins, and stack frames from the disk-loaded runtime bundle carry host sourceURLs. A conformant implementation of the criteria as written can still print the host install path from the prompt.
Resolution: add a short subsection (or explicit open question) enumerating the remaining host-path-bearing surfaces and their treatment (virtualized, closed, or deliberately accepted with rationale), and extend criterion 13 accordingly.

**9. The Motivation's "reports an `ENOENT` for the host root" is stale against current main.** — **Minor.**
Evidence: observed behavior today is a typed refusal — `typed filesystem authorization refused: … host path has no authenticated logical-root binding`, surfacing in JS as `code: UNKNOWN, message: Permission denied` — not host `ENOENT` (empirical run of the armed binary; consistent with WP5's staged adapters landing after this passage was drafted). The bug the spec fixes is real either way, but a normative doc's motivating facts should match its revision date.
Resolution: update the sentence to describe the typed-refusal shape (which incidentally strengthens the §9 error-taxonomy case — today's error is both wrong-class and unhelpful).

**10. The `undefined`-display policy silently diverges from the Node precedent the doc elsewhere leans on.** — **Minor.**
Evidence: §9 says "a declaration or other empty completion displays nothing," but Node/Deno print `undefined` for `let x = 1`. Permitted by compatibility priority 5/6, but the divergence should be acknowledged as deliberate (as §9 does for non-fatal async errors).
Resolution: one clause noting the divergence, or align with Node.

**11. Small consistency and precision items.** — **Minor (grouped).**
(a) Open question 7 lists reverse history search as a *future* affordance, but rustyline's Ctrl+R ships today, is advertised in `.help`, and is pinned by tests (`repl/mod.rs:628,1309-1315`) — state the v1 status of line-editor built-ins. (b) §1/§14 name only `IBEX_REPL_PROMPT`; the code also honors legacy `EX_REPL_PROMPT` (`repl/mod.rs:91-98`) — include or retire it. (c) §4's "typed filesystem metadata/list decision" should name the WP0 action (`fs:list`, per WP5's stat/enumeration edges) — "metadata" is not a vocabulary action. (d) Making `process.cwd()` a virtual non-capability changes the generated classification of the cwd surfaces (`__exactGetCwd` stays closed); the spec should require the LLP 0021 registry update in the same change, per the no-unclassified-surface invariant. (e) §3 should state the per-principal most-specific binding rule explicitly (root addresses `node_modules` *through* `/project` because package bindings never match a root principal — `crates/capsec-semantics/src/arming.rs:179-219`); the current "package bindings are not mounted" sentence leaves the nested-path question open. (f) §2 program mode should state the stdin program's module mode (CJS/ESM; static `import` allowed?) and whether extensionless TS applies (ties into concern 4).

## 4. Suggestions

- **Cite prior art for the mount model**: WASI preopens/libpreopen and Capsicum's `openat`-relative discipline are the closest ancestors of §3 and would both strengthen the argument and import known lessons (e.g., WASI's experience with `..`-at-mount-root and path_open semantics). WP5 already uses `openat`/`O_NOFOLLOW`; the spec could align its normalization language with that mechanism.
- **Add a `.mounts` (or fold into `.help`) presentation command** showing the virtual mount table and current virtual cwd. It is parity-safe by construction (the table is exactly what prompt code can discover by probing) and would materially reduce user confusion during the cutover from host-path expectations.
- **Give first-Ctrl+C-during-evaluation immediate feedback** (e.g., "evaluation continuing — press Ctrl+C again to end the session") so §15's two-press contract is discoverable rather than appearing dead.
- **Reserve the `repl:` scheme in the module loader** (hard error like the unknown-`node:` guard, LLP 0004 §Resolution order step 3) so §5's "cannot collide with a module specifier" is enforced, not assumed.
- **Make `.help` output itself a plain-protocol fixture**: criterion 14's "exercised end to end" needs a command enumeration; pinning `.help` in a transcript makes the enumeration self-updating.
- **Consider a `_` alias for `$_`** (or explicitly note the divergence): Node muscle memory is `_`, and §6 already reserves the namespace carefully.
- **Note in §6/guidance which persistence mechanism is intended for Hermes** (shared global lexical scope across `evaluateJavaScript` calls vs. a session record), since the guidance's "explicit session environment" and open question 4 currently leave the implementer to rediscover the constraint space.

## 5. Open questions

Beyond the document's own eight (which are good, especially 4, 5, and 6), these must be answered to finish the contract:

1. What is the authority posture over `/home` — and should a machine-global cache be visible to session JavaScript at all (concern 1)?
2. What is the deterministic JS/TS tiebreak for ambiguous prompt input, and which transform tier does the prompt share (concern 4)?
3. What does a `with { … }` authority attribute *do* at runtime at the prompt — inert-with-report, or typed dynamic-grant request (concern 5)?
4. Does the patched Hermes get a trap-bypassing introspection primitive for completion, or is the §13 guarantee weakened (concern 6)?
5. How are inputs delimited and how is EOF-with-incomplete-input handled in plain protocol mode; what streams does transcript determinism cover (concern 7)?
6. What is the disclosure treatment of `process.execPath`, `os.homedir()`, `os.tmpdir()`, and runtime-bundle stack frames (concern 8)?
7. Can Hermes's shared global lexical scope deliver §6's redeclaration semantics across separate evaluations, and if not, what is the documented compromise (doc's own OQ4 — needs an answer before criterion 6 is testable)?

## 6. Readiness verdict

The direction is right, the code archaeology is accurate, and most of the contract is well drafted — but material concerns remain in safety (concerns 1, 2), normative correctness (3, 4), coherence with LLP 0014/0021 (5), feasibility (6), and testability (7, 8). Per the stated READY bar (no unresolved material correctness, coherence, feasibility, safety, or decision-quality concern), this revision is not there yet; all identified issues look resolvable with targeted text revisions rather than redesign.

# Independent Design Review: LLP 0022 — REPL Behavior and Semantics (rev b2a9580177e0, round 2)

## 1. Overall assessment

This is a strong, unusually honest spec, and the right document to exist. It takes a bug that is "wrong twice over" — `fs.readFile("README.md")` at the armed prompt becoming a host lookup for `/README.md` and then a mislabeled permission error — and correctly diagnoses it as a conflation of three concepts (shell host cwd, armed logical binding, JS-visible cwd) rather than patching the symptom. Every step of that causal chain checks out in the code: the armed engine closes native cwd disclosure (`src/engine/hermes_runtime.cc:1653-1656`), the JS facade falls back to `/` (`src/builtins/process.js:8,69-82`), `fs` eagerly absolutizes against it (`src/builtins/fs.js:570-602`), the armed host joins relative paths against the Rust process cwd and prefix-matches bindings (`src/host/mod.rs:288-301`), and unbindable host paths refuse with "host path has no authenticated logical-root binding" (`crates/capsec-semantics/src/arming.rs:206-208`). The proposed fix — a WASI-preopen-style virtual namespace with a single `/project` mount and root-only virtual `chdir` — is the correct architectural move, and it satisfies the exact condition the registry already recorded for reopening the cwd surface ("Keep closed unless cwd is virtualized or scoped without changing other principals' resolution," `capsec/registry/legacy-capability-reconciliation.json:112`).

Equally important, the document is right that the REPL needs a written contract beyond the bug. The divergences it catalogs are all real and all verified: `.env` dumps the raw host environment via Rust ambient authority around the armed gate (`src/bin/ibex/repl/mod.rs:966-971`); `.load` is a raw `tokio::fs::read` plus bare eval outside the module and capability pipeline, with the host path as the sourceURL (`src/bin/ibex/engine/hermes.rs:1145-1158`); tab completion evaluates its base expression via `Function('return (' + expr + ')')()` (`src/bin/ibex/repl/mod.rs:291-336`), neutralized-but-not-safe under lockdown's tamed `Function` (`src/engine/hermes_runtime.cc:2442-2443`); the import path routes prompt `with { needs: … }` attributes into the legacy `Exact.setModuleCapabilities(0, …)` oracle and prints a false "[capability granted]" acknowledgment (`src/bin/ibex/repl/mod.rs:818-836`); the async-IIFE wrap drops `let`/`const` from top-level-await inputs (`src/bin/ibex/repl/mod.rs:1174-1186`); and native promise unwrapping assimilates arbitrary thenables and consults `IBEX_AWAIT_UNWRAP_TIMEOUT_MS` post-arming (`src/engine/hermes_runtime.cc:3044-3100`). A spec that pins these down, with a staged path and a pinned v1 persistence baseline instead of pretending target semantics ship now, is exactly the right shape.

My reservations are at the level of precision, not direction. Three things need tightening before this should govern implementation: the cross-principal semantics of the virtual namespace are ambiguously worded (the "root-visible only" mount table sits awkwardly against "relative resolution for all code uses the session cwd" and against packages holding project-root grants); the terminal-escape set is enumerated in a way that omits several dangerous C1 controls and conflates bytes with code points; and the §6 failure-publication rule contradicts the pinned v1 baseline for lexical bindings initialized before a later throw. Each has a small, concrete fix. With those landed, this is a spec I would be happy to see frozen.

## 2. Strengths

- **The virtual namespace design (§3) is correct and precedented.** One mount, POSIX-shaped everywhere, `/` as namespace root rather than an alias for `/project`, outside-mount errors distinct from `ENOENT`, and the explicit refusal to mount the `home` cache binding (which I verified is indeed the machine-global runtime cache installed as a logical root — `src/bin/ibex/runtime.rs:1918-1945`) closes a real cross-project disclosure/poisoning channel that a naive "mount all bindings" design would have created.
- **The path grammar paragraph (§3) does the unglamorous work.** Lexical-first normalization then containment, `realpath` returning virtual spellings, `readlink` as data, `/` as synthetic readable metadata, invalid-UTF-8 refusal pinned as a v1 deviation — this is the level of detail path-security specs usually lack.
- **§4's root-only virtual chdir is the standout decision.** It simultaneously fixes the bug, removes the process-global host `chdir(2)` dependence (today's `__exactSetCwd` really does call host `chdir`, `src/engine/hermes_runtime.cc:1691-1699`), closes the package→root cwd-redirection channel including the callback-after-return case, and satisfies the registry's recorded reopening condition. The four-step commit protocol matches WP5's retained-parent discipline.
- **The affordance-parity rule (§10) with its single terminal-operator-state exception** is a genuinely good invariant — it generalizes the `.env` withdrawal into a principle that will keep future dot-commands honest, and the exception is drawn exactly where it must be (state the CLI needs to operate the terminal, captured pre-arming, never exposed to JS).
- **§8's inert-prompt-attributes rule is the honest consequence of LLP 0014 + LLP 0021** (attributes are build-time inputs, stripped before the engine; the armed snapshot is immutable), and it explicitly retires the current dishonest acknowledgment. The required truthful no-effect notice is the right UX for a security runtime.
- **The pinned v1 persistence baseline (§6)** — deviations enumerated, frozen by fixture, narrowing always permitted, silent widening forbidden — is the right way to ship on an imperfect engine seam without letting the imperfection become the contract.
- **§13's completion gating is exactly right.** It correctly identifies that syntactic screening is necessary but insufficient and that pure-JS reflection runs Proxy traps; gating member completion on a native trap-free primitive with a no-candidates fallback is the only safe design, and it is feasible given the project already maintains a patched Hermes.
- **The staging section and acceptance criteria are unusually disciplined.** Three strata with conformance claims required to name their stratum; 29 acceptance items that are concrete, mostly automatable (plain-transcript mode as the scriptable projection is a very good testability move), and that include the vendored-artifact parity check (criterion 29) which matters given LLP 0005's hermetic-default builds.
- **Registry coherence is real, not asserted.** I verified the rows the doc leans on: `process:cwd` closed with the virtualization condition; `global:process.chdir` closed; `global:process.exit` / `__exactExit` / `__exactHostExit` closed ("Runtime termination exits the shared host process…"); `global:process.exitCode` closed ("shared mutable runtime state") — §15's cooperative root-only lifecycle is a faithful reopening of exactly those rows. The post-arming `IBEX_AWAIT_UNWRAP_TIMEOUT_MS` consultation it orders removed is real (`src/engine/hermes_runtime.cc:3090`).
- **Mode matrix (§2) and stdin ownership** are well-chosen: program mode matches Node's piped-stdin behavior, plain transcript mode gives a deterministic fixture surface, and always-EOF `process.stdin` at the prompt removes an entire class of editor-contention bugs.

## 3. Concerns

1. **Cross-principal virtual-namespace semantics are ambiguous.** — **Material.** §3 says "Mount resolution is root-visible only: a root-principal lookup resolves against this table, and package bindings never match it… package principals keep their own binding view per LLP 0021," while §4 says "Relative resolution for all code in the runtime uses the session cwd" — which produces `/project/...` spellings for package code too. LLP 0014's canonical example grants packages `path-tree` resources rooted at `project` (llp/0014 §The generated artifact), and the armed host normalizes host paths through the longest owner-filtered binding (`crates/capsec-semantics/src/arming.rs:184-208`; LLP 0021 WP8: "Package roots match only their exact package owner"). As written, one plausible reading — package-principal lookups do not resolve against the mount table — would make every package-attributed relative read incoherent; the other reading makes "root-visible only" misleading. The spec never states what a package-attributed operation on a `/project/...` virtual path does, nor how a package's own files are spelled in the virtual namespace. **Resolution:** rewrite the paragraph to state the model explicitly — I believe the intended one is: a single runtime-global virtual namespace and one mount table for virtual→binding translation, with per-principal *authority* (and host-side longest-binding owner normalization) deciding access; "root-visible only" should become "no virtual path addresses a package binding." Specify the package-attributed `/project/...` case and the spelling of package-root files.

2. **The terminal-escape set (§9) is under-inclusive and conflates bytes with code points.** — **Material.** "C0 controls, `ESC`, and the single-byte C1 introducers (0x9B CSI, 0x9D OSC) included" omits DCS (U+0090), SOS (U+0098), PM (U+009E), and APC (U+009F) — all C1 introducers that some terminals honor when the code points appear in UTF-8 output — and says nothing about DEL (0x7F). In a UTF-8 stream (§14 mandates UTF-8) there are no "single-byte" C1s; the dangerous artifact is the *code point* U+0080–U+009F however encoded. Acceptance 16 tests only ESC/CSI/OSC, so a minimum-compliant implementation would pass while leaving APC/DCS injection open. **Resolution:** specify the exhaustive set — all C0 (with a stated policy for the REPL's own intentional newlines/tabs), DEL, and all C1 code points U+0080–U+009F regardless of encoding — and extend acceptance 16 to at least one non-CSI/OSC C1 (e.g., APC).

3. **§6 failure publication contradicts the v1 baseline for initialized lexical bindings.** — **Material.** "A runtime exception publishes state per ordinary script semantics within the input: effects and assignments completed before the throw persist" implies `let x = 1; throw new Error()` leaves `x` bound (one-growing-script semantics). But the v1 baseline persists declarations "by hoisting… to a session binding," and any capture-after-completion mechanism loses bindings initialized before a mid-input throw, while a rewrite that preserves them typically breaks within-input TDZ — which §6 separately forbids ("must not implement persistence in a way that changes semantics **within** one input"). The three-item deviation list does not cover this case, and §6 forbids silently exceeding the list, so a fixture author cannot know what to pin. **Resolution:** add the `let x = 1; throw` case explicitly — either require persistence (and acknowledge the implementation burden), or add it as a fourth pinned deviation (initialized-but-uncaptured lexical bindings of a failed input are lost and the name is redeclarable) — and reference it from acceptance 7.

4. **Stratum-1 "Rust-side output escaping" is not implementable as labeled while display is a flat colored string from JS.** — **Material (small fix).** Today the value display arrives in Rust as one string already containing ANSI styling from `Exact.inspect(_val, {colors: true, …})` (`src/bin/ibex/repl/mod.rs:63-80`); Rust-side escaping cannot distinguish REPL-authored styling from value-embedded escape sequences on that channel, so the §9 guarantee cannot be met in stratum 1 with inspection colors on. §Staging requires conformance claims to name their stratum, so this mislabel could underwrite a false stratum-1 claim on a security property. **Resolution:** one staging sentence: under stratum 1, inspection colors are disabled (or styling moves Rust-side) so escaping is total; the colored-inspection + escaping combination arrives with the structured evaluation seam.

5. **"When color is disabled, REPL-authored output contains no ANSI sequences" (§9) conflicts with `.clear` and line-editor control on a TTY.** — **Minor/Non-blocking.** With `NO_COLOR` set on a real TTY, `.clear` must still emit `ESC[H ESC[2J]` (as today, `src/bin/ibex/repl/mod.rs:907-911`), and bracketed-paste/redraw sequences are inherent to §14's required editing behavior. The rule as phrased makes those non-conformant. **Resolution:** scope the no-ANSI rule to *rendered content styling*; terminal-control functions of the editor and `.clear` are governed by TTY presence, not the color predicate. (The non-TTY fixtures in acceptance 25 stay as-is.)

6. **Command-argument grammar has two unstated edges (§11).** — **Minor/Non-blocking.** ".load <path> — the argument is the rest of the line, verbatim" does not say whether the separating whitespace is consumed (paths may legally begin with spaces), and the spec never states whether a command line can enter §5 multiline continuation (e.g., `.time {`). **Resolution:** define the argument as the remainder after the first whitespace run following the command name, and state that command inputs never enter continuation — an incomplete `.time` argument is an immediate recoverable error.

7. **Cooperative `process.exit(n)` unwind semantics are unspecified (§15).** — **Minor/Non-blocking.** Node never executes code after `process.exit()`; a cooperative session-layer request could plausibly let the current evaluation continue to a checkpoint. Observable divergence either way, and acceptance 21 doesn't cover it. **Resolution:** state whether evaluation unwinds at the call (and by what mechanism) or exit is deferred to evaluation completion, and add a `process.exit(7); markerEffect()` fixture.

8. **`ibex:stdin` is not reserved in the resolver.** — **Minor/Non-blocking.** §5 reserves `repl:` with a hard resolver error, but §2 mints `ibex:stdin` as a module identity without reserving the scheme; `import("ibex:stdin")` behavior (from the prompt or from a file) is undefined, and an unreserved scheme could later collide. **Resolution:** reserve the `ibex:` synthetic scheme alongside `repl:` (same hard-error rule), or define its resolution explicitly.

9. **Package-attributed `process.cwd()` reads are opened without discussion.** — **Minor/Non-blocking.** §4 opens the virtual cwd read to all principals ("virtual read open" registry row in §Staging). That lets any package observe root's navigation within `/project` (directory names it may hold no grant on) by polling `cwd()`. Probably the right Node-compat call, but it is a small deliberate disclosure that the doc — otherwise scrupulous about disclosure — doesn't acknowledge. **Resolution:** one sentence accepting it with rationale (names within the project namespace are considered non-secret to co-resident packages) or scoping package reads.

10. **`.load` source identity and grammar-by-extension are unspecified (§5/§11).** — **Minor/Non-blocking.** `.load` content is "a single REPL input," which gives it the `repl:<n>` source name — losing the file association in stack frames — while today's `.load` leaks the *host* path as the sourceURL (`src/bin/ibex/engine/hermes.rs:1157`), which the new design must not reproduce. Separately, TS-grammar-always means `.load foo.js` can parse differently from `import "./foo.js"` (`a<b>(c)`). **Resolution:** specify the synthetic source name for loaded content (e.g., `repl:<n>` carrying the virtual path, virtual spellings only), and either state the `.js`-under-TS-grammar divergence for `.load` explicitly or parse by extension.

## 4. Suggestions

- **Extend the terminal-safety obligation to `-p/--print` and `ibex eval`.** §Scope binds them only to path semantics, but `-p` renders runtime values to a terminal exactly like the REPL does; the shared renderer seam in Implementation guidance makes extending the escaping rule nearly free.
- **State the transcript rationale for affordance parity.** The strongest argument for withdrawing `.env` even though JS cannot read dot-command output is that session transcripts are shared, logged, and increasingly consumed by agents driving the PTY; closed state printed to the terminal is closed state exfiltrated. One sentence in §10 would preempt the "but the operator can run `env` themselves" objection.
- **Note the POSIX divergence of lexical-first `..` collapse.** `/project/a/../b` where `a` is a symlink differs from host `open()` semantics (which traverse the link's physical parent). The grammar already implies this; naming it as a deliberate capability-system choice (matching `path.resolve` and WASI-style discipline) would prevent a future "bug report" from reopening it.
- **Lean into the supervisor/worker architecture for §15.** Beyond the second-interrupt guarantee, a PTY-owning supervisor also delivers the §14 crash-restore guarantee for *un*catchable engine deaths, isolates history writing from the engine, and gives plain-transcript framing a natural single writer. If the Hermes async-interrupt probe (open question 6) is at all doubtful, the supervisor is likely the durable answer and could be named the presumptive design.
- **Specify `require()` at the prompt.** §8 covers import syntax; whether CommonJS `require` is available to prompt code (it is today, and Node's REPL has it) is unstated — it should obey the same builtin allowlist and attribution rules either way.
- **Add SIGTSTP/SIGCONT to §15.** Suspend/resume is a classic raw-mode terminal-corruption source; one line ("terminal restored on suspend, editor state reinstated on resume") plus a PTY fixture would close it.
- **Consider OSC 133 semantic prompt marks** (emitted only under the color/TTY predicate) as a permitted presentation-level affordance — cheap, helps terminals and agent tooling delimit prompt/output regions, and composes with plain transcript mode's framing.
- **Small registry-filing nit:** removal of the `IBEX_AWAIT_UNWRAP_TIMEOUT_MS` consultation is an engine-code obligation listed under stratum 3 "registry and vocabulary obligations"; filing it under stratum 2 (it dies with the structured evaluation seam) would be cleaner.

## 5. Open questions

The document's own nine are well-chosen; questions 4 (engine mechanism for true session semantics) and 6 (Hermes interruptibility) are the two whose answers most shape the implementation. I would add:

1. Should package-attributed `process.cwd()` read return the session cwd, a package-scoped value, or a typed denial (Concern 9)?
2. What is the synthetic source identity of `.load`-ed content, and do stack frames from it carry the virtual path (Concern 10)?
3. Does cooperative `process.exit` unwind the current evaluation immediately, and by what mechanism on the current engine seam (Concern 7)?
4. Is `require()` (and `require.resolve`) part of the supported prompt surface, and under which attribution rules?
5. When the structured evaluation seam lands, does interactive mode render *through* the plain-transcript record stream (one renderer, two framings), making transcript fixtures the oracle for interactive display content?
6. For the v1 baseline, what exactly does the session-binding hoist do to `var`/function declarations versus `let`/`const`/`class` — the fixture set for §6 needs the per-declaration-kind mapping stated once, normatively.

## 6. Readiness verdict

The direction, the security model, the staging honesty, and the acceptance discipline are all right; the remaining defects are precision faults with small, well-defined fixes (Concerns 1–4). Until the namespace wording, the escape set, the failure-publication baseline, and the stratum-1 escaping label are resolved, the spec can be read two ways in places where an implementer must not have two choices.

# Review: LLP 0022 — REPL Behavior and Semantics (round-3 revision, 2026-07-12)

## 1. Overall assessment

This is an unusually strong specification, and the round-3 revision shows the compounding value of the review loop: the hardest problems a REPL spec in this architecture faces — arming a session that has no entry, giving JavaScript a coherent path model without disclosing host paths, keeping interactive affordances from becoming side channels, and being honest about what Hermes can and cannot interrupt — are all confronted directly rather than waved at. The document's most distinctive virtue is that its motivation is *true*: I verified every one of the seven defect claims against the code, and all seven are accurate, including the subtle ones (`.env` enumerating the raw host environment at `src/bin/ibex/repl/mod.rs:966-971`; the "capability granted" message for a grant that never happens at `repl/mod.rs:819-836`; completion evaluating its base expression via `Function('return (' + expr + ')')()` at `repl/mod.rs:283-347`; the statement-form TLA wrapper discarding lexical bindings at `repl/mod.rs:1174-1186`; thenable assimilation plus the post-arming `IBEX_AWAIT_UNWRAP_TIMEOUT_MS` read at `src/engine/hermes_runtime.cc:3040-3100`; `.load` as a raw host read with host-path source identity at `src/bin/ibex/engine/hermes.rs:1145-1158`; and the live raw bridges `__exactExit` / `__exactRealpath` / `pkgRoot` serialization at `src/engine/hermes_runtime.cc:1704-1727`, `src/engine/hermes_runtime_fs.cc:2551-2591`, `src/host/abi.rs:2182`). A spec that diagnoses its own codebase this precisely earns trust for its prescriptions.

The prescriptions are mostly right. The identity-versus-spelling move in §3 is the correct conceptual foundation (it matches WASI preopens and Capsicum, as claimed, and it dissolves the actual bug: `process.cwd()` falling back to `/` in `src/builtins/process.js:69-81`, `fs`'s eager `_resolvePathFromCwd` at `src/builtins/fs.js:570-601`, and the armed host's join against the Rust process cwd at `src/host/mod.rs:287-298` producing the "no authenticated logical-root binding" refusal at `crates/capsec-semantics/src/arming.rs:206-208`). The frozen v1 session record with exactly four pinned deviations is the best section in the document — the deviations are precisely those that fall out of a realistic wrapper-plus-record implementation, which means the frozen algorithm is implementable, and freezing it as a versioned contract rather than an aspiration is exactly how a Spec should handle an engine seam that does not exist yet. The staging discipline (stratum-scoped conformance claims) and registry-generated fixture inventory are coherent with LLP 0021's no-unclassified-surface invariant, and the claims I checked against the registry are accurate (the cwd-opening condition quoted in §4 exists verbatim at `capsec/registry/legacy-capability-reconciliation.json:112`; `process:cwd` is deny-only today at `capability-definitions.json:279-292`; `stdio:query` is a real typed action; no-effect logical branches exist in the generated registry).

It is not yet READY, for a small number of localized but material reasons. The most serious is an internal inconsistency in module identity: §3's caller-relative binding mapping, fed into §6's cache-identity rule and pinned by AC6, mandates per-principal double instantiation of package modules (root's `import "foo/util.js"` and foo's own `require("./util")` get different cache identities), which breaks module singletons, contradicts §10's shared-instance attribution model, and diverges from Node without acknowledgment. Second, §9's v1 descriptor-only display walk cannot satisfy its own no-Proxy-trap rule before the stratum-2 trap-free primitive exists, and the text reads as if it can. Third, the single-mount namespace is silent about package roots that do not live under the project root — pnpm stores and hoisted workspaces fail closed via the staged-symlink containment rule with no acknowledgment, consequence note, or open question. Fourth, the session manifest — the security-critical new artifact — has no staging stratum, no digest-domain relationship to LLP 0021's frozen domains, and an ambiguous program-mode arming sentence. Each fix is a paragraph, not a redesign; the document is one focused revision from READY.

On the scope question the document poses about itself (open question 10): the behavior-contract scope is right, and I would keep it. The three mechanism layers should become child LLPs — particularly the virtual-path/runtime-state ABI, which is shared with the one-shot surfaces and embedders and therefore should not have a REPL spec as its permanent owner — but the split is document structure, not semantics, and nothing here blocks on it.

## 2. Strengths

- **Verified, honest motivation.** Every defect claim in §Motivation checks out against the code (citations above). This includes the subtle parenthetical that lockdown "often neutralizes" completion evaluation — correct, because arming sets `IBEX_LOCKDOWN=1` structurally (`src/bin/ibex/runtime.rs:1650`) and lockdown tames the `Function` constructor (`src/engine/hermes_runtime.cc:2415-2440`), so the completion query throws into its catch and yields nothing.
- **§3 identity versus spelling.** Making authorization and caching key on an authenticated tuple rather than a string, with display spelling as presentation only, is the correct capability-system move and structurally kills the string-shape inference the implementation guidance rightly condemns (`path.is_absolute()`-style logic in the current adapters).
- **§3 host-path observables as a generated table.** Extending the no-host-path property from `process.cwd()` to a registry-derived table of every path-bearing observable (execPath, argv, `import.meta`, stack frames, error `path`, watch events, source maps) closes the "guarantee stated over three facades" failure mode the raw-bridge audit exposes. The `home`-binding exclusion is well-grounded: the binding is really the machine-global cache (`src/bin/ibex/runtime.rs:1918-1945`, `runtime_cache_dir()` at `runtime.rs:3445-3452`), and both the poisoning and the `/home` shadowing arguments are correct.
- **§4 sealed native cwd.** Root-only virtual `chdir` over a retained identity, with monkeypatch immunity because native resolution never consults the JS facade, and stale-identity detection for replaced directories — this is a complete design, and it correctly cites and implements the registry's recorded opening condition (`legacy-capability-reconciliation.json:112`) rather than contradicting the current deny-only row (`capability-definitions.json:279-292`), with the regeneration staged in stratum 3.
- **§6 frozen v1 session record.** Exactly four deviations, pinned by fixture, with narrowing declared a versioned contract change. This is the most testable treatment of REPL binding semantics I have seen in a spec, and deviation (d) (lexical bindings of a throwing input are unpublished) is exactly what a publish-at-end wrapper yields — evidence the algorithm was designed against a real implementation strategy.
- **§7/§9 no thenable assimilation, structured outcomes.** Directly retires the verified defect (`hermes_runtime.cc:3040-3054`), with the instrumented-thenable acceptance test (AC12) that would have caught it.
- **§9 terminal safety.** Full C0/DEL/C1 escaping including UTF-8-encoded C1s, the explicit observation that naming CSI/OSC alone is insufficient (DCS/SOS/PM/APC/ST), and the structural insight that a flat pre-colored string from JS cannot be escaped safely — which precisely indicts the current `Exact.inspect(_val, {colors: true})` path (`repl/mod.rs:63-65`) and correctly forces stratum-1 inspection colors off.
- **§10 affordance parity with one named exception.** "Closed state printed to the terminal is closed state exfiltrated" is the right frame for the transcript-consuming-tooling era; the terminal-operator-state carve-out is narrow, principled, and distinguished from `stdio:query`.
- **§10 raw-bridge sealing with a generated inventory.** The right response to the verified `__exactExit`/`__exactRealpath`/`__exactStdinRead` reachability, with red-team fixtures addressing bridges by name (AC16) and an inventory check so a new bridge cannot ship unsealed.
- **§2 mode design.** Plain transcript mode as the byte-deterministic, unconditionally-ANSI-free projection of the interactive session is an excellent testability decision; program mode's `ibex:stdin` identity and source-goal matrix (§5) resolve real Node-ecosystem ambiguities deliberately. Today's dispatch has no non-TTY handling at all (`src/bin/ibex/main.rs:438-466`), so this is well-specified new ground.
- **§15 honesty about interruption.** The three-outcome cancellation model, the presumptive supervisor/worker architecture with its three independent justifications (second-interrupt guarantee, terminal restoration on uncatchable death, single transcript writer), and the staging note that mid-evaluation cancellation is excluded from stratum 1 form a coherent, honest treatment of the hardest feasibility problem.
- **Acceptance criteria quality.** 32 criteria, generated-inventory framing, instrumented-adversary style (getters, Proxy traps, thenables, marker env vars, PTY assertions), and the closing admission that nearly everything is currently uncovered.

## 3. Concerns

**1. Module-cache identity as written mandates per-principal double instantiation of modules. — Blocking**
Evidence: §3 maps a virtual path "to the most specific binding owned by the *calling* principal," and the logical path identity includes "binding owner." §6 then makes "the authenticated logical path identity of §3" the module-cache key, and AC6 pins "two principals resolving the same spelling under different bindings do not share a module-cache entry." Consequence: root's `import "foo/util.js"` resolves under the project binding (owner: none) while foo's own `require("./util")` resolves under foo's package binding (owner: foo) — two cache entries, two instances of the same file. That breaks module-level state, singletons, and `instanceof` across the root/package boundary for the everyday deep-import case; it contradicts §10, whose attribution model ("calling package code from the prompt does not launder its effects") presumes root holds references into a package's single instance; and it silently diverges from Node and from LLP 0013's one-compartment-per-package model, violating the document's own rule that divergences be documented. Resolution criterion: separate authorization identity (caller-relative — correct as specified) from module identity. Key the module cache on an owner-normalized identity or on `(runtime, retained platform object identity)` — the latter gives both single instantiation of the same file and non-unification of genuinely different objects under coinciding spellings — and reword §6 and AC6 to test the actual aliasing hazards (cwd-independence; no unification of *distinct authenticated objects*), not spelling-under-different-bindings.

**2. §9's v1 display contract is self-contradictory before the trap-free primitive exists. — Material**
Evidence: §9 states "Display must not invoke getters, Proxy traps, …" and simultaneously "v1 renders with a descriptor-only walk," with proxy state read through the native snapshot "when [it] exists." But a descriptor-only walk implemented above the current engine seam (pure JS or existing JSI) runs `getOwnPropertyDescriptor`/`ownKeys`/`getPrototypeOf` traps on any Proxy, and a Proxy is undetectable without exactly the stratum-2 primitive (§Staging; §13 concedes this for completion: "pure-JavaScript reflection … does not satisfy this section"). Since *any* object might be a Proxy, "unrecognized exotic objects are opaque" cannot be evaluated pre-primitive; a conforming-to-§9-v1 implementation would fail AC19. Resolution criterion: state explicitly which stratum the descriptor walk belongs to. Either (a) the descriptor walk itself gates on the stratum-2 trap-free primitive and pre-primitive display renders every non-primitive by type tag only, or (b) AC19's Proxy clauses are explicitly stratum-2-scoped and the interim trap exposure is named as an accepted stratum-1 gap. Option (a) matches the document's "inert is acceptable, unsafe is not" stance.

**3. Out-of-project package roots have no story, and the symlink rule closes pnpm-style layouts unacknowledged. — Material**
Evidence: §3 mounts only `/project` and asserts package files are "reachable at their `/project/node_modules/<name>/...` spelling." LLP 0021 allows package-root bindings anywhere on the host (every graph node has its own binding; the arming code builds them from arbitrary host paths, `src/bin/ibex/runtime.rs:1830-1852`). A package root outside the project binding (pnpm store, hoisted workspace above the project, monorepo sibling) has no virtual spelling at all — so `__dirname`, `import.meta.url`, error `path`s, and `require.resolve` for such a package have no defined value under §3's table — and the staged-symlink rule (step 4: refuse "if it left every mount") refuses the `node_modules/<name>` symlink into a store outright, for every principal, including the owner whose armed binding covers the target. The Consequences section is silent; no open question covers it. Resolution criterion: specify the v1 disposition explicitly — e.g., session arming refuses a graph whose package bindings are not contained in the project binding, with a named diagnostic; or mount containment for a principal includes bindings that principal owns; or synthetic per-package mounts — and add the consequence note and an acceptance criterion. "Unsupported in v1, fail closed at arming with this exact error" is an acceptable answer; silence is not.

**4. The session manifest is under-specified for a security-critical artifact. — Material**
Evidence: §1 defines a "digest-bound artifact" whose content is essentially the LLP 0021 armed snapshot's (root binding and object identity, graph and import edges, registry/profile identities, root import surface), yet: it is absent from all three staging strata; LLP 0021 froze the digest domains ("Digest encoding and domains are frozen") and the manifest names no domain and no relationship to `ibex:capsec:armed:1`; and no acceptance criterion tests its digest binding or authentication (AC25 is behavioral only). Separately, the program-mode sentence — "arms with that source as the entry, so its graph is derived exactly as a file entry's would be" — is mechanically ambiguous: at runtime a file entry's graph comes from the committed policy artifact (WP9's projection; `src/bin/ibex/runtime.rs:1856-1912`), not from analyzing the entry, so either the sentence is vacuous (same artifact as interactive, plus main-module identity) or it implies runtime graph derivation from stdin source, which would be a large unstaged mechanism. Resolution criterion: state whether the session manifest *is* the armed snapshot (with an absent/synthetic entry) or a distinct artifact with its own schema and digest domain; assign it a staging stratum; rewrite the program-mode bullet to say precisely which inputs differ from interactive arming; and add a digest-binding acceptance criterion.

**5. The new REPL input transform is an unpinned rewrite tier under LLP 0019. — Material**
Evidence: LLP 0019 (Accepted) fixes that the Hermes-compat rewrite "exists in exactly **two tiers**, by design," gated by a shared conformance corpus. Prompt input on shipping Hermes needs the same compat lowering as any source (for-of scoping, async generators), and LLP 0022's stratum-2 transform ("emitting source maps and preserving script-goal semantics under import/TLA lowering") is new machinery whose relationship to the two tiers and the corpus is never stated — despite LLP 0019 being listed as Related. Resolution criterion: one paragraph naming which transform authority serves prompt/`.load`/program-mode input, and either wiring the LLP 0019 corpus (a third system-under-test over the same fixtures) or amending LLP 0019 in the same change.

**6. fd-0 and terminal-fact observables are not pinned per surface. — Minor/Non-blocking**
Evidence: §2 specifies "the specified empty, immediately-ended non-TTY view **or** a single typed session-owned denial," and AC17 accepts either per route, so two conforming implementations can disagree on whether `fs.readSync(0)` returns EOF or throws — in a document that elsewhere pins observables via a generated table precisely to prevent this. The same applies to a denied `stdio:query` (`isTTY`) read, where a throwing read would break Node-shaped feature detection. Resolution criterion: extend the generated-table treatment (§3 style) to fd-0 routes and stdio facts, fixing EOF-view versus typed-denial per surface.

**7. The cancellation outcome model has no state for a defeated request. — Minor/Non-blocking**
Evidence: §15 says a request "resolves to one of" accepted/unavailable/failed, but Hermes-style async breaks surface as JS-catchable throws: user code can catch the break and keep running, so the request may never resolve. The second-interrupt row already covers the safety property, but the outcome enumeration is over-strong, and "accepted" must be defined by the evaluation actually returning (plus a consistency check), never by the injected throw being raised. Resolution criterion: add a "pending/defeated — second-interrupt rule applies" outcome (or state requests may remain unresolved), and define acceptance by observed evaluation completion.

**8. AC24 is not executable as phrased, and the env-channel inventory has in-process members. — Minor/Non-blocking**
Evidence: "setting any inventoried environment variable … after arming has no observable effect" — a host env variable cannot be set from outside after the process starts; the testable property is "set at launch, consulted only post-arming ⇒ no effect," and §1 explicitly permits some variables to be captured pre-arming (prompt, color, history), which *do* have effects. Note also that arming itself writes process env consumed later by the engine (`IBEX_LOCKDOWN` at `runtime.rs:1650`; `IBEX_ENDOW` set/removed at `runtime.rs:1884-1888`), so the inventory must classify runtime-internal env channels too. Resolution criterion: reword AC24 to distinguish captured-pre-arming (documented, observable) from retired/inert variables, each with a launch-time fixture, and include the internal channels in the inventory.

**9. Two specified security rules have no acceptance criterion. — Minor/Non-blocking**
Evidence: §1's no-rc-file rule (ambient file presence must not become root-principal execution — the highest-leverage regression this spec forbids) has no fixture; `.load`'s §3/§10 obligations (outside-mount refusal, typed read decision under the operator-submission principal) are asserted nowhere (AC14 covers only grammar). Resolution criterion: add a red-team fixture planting rc-named files in project and home and asserting inertness, and a `.load /etc/passwd`-class fixture asserting the outside-mount error and decision evidence.

**10. §8's hard error is prompt-scoped; `.load` content and program-mode stdin are unaddressed. — Minor/Non-blocking**
Evidence: "Authority-bearing import attributes are a hard error **at the prompt**"; `.load` evaluates content "as one input" and program mode is "file-execution semantics," but what file execution does with runtime-encountered authority attributes (normally stripped at build time per LLP 0014) is not stated here. Resolution criterion: one sentence extending the hard error to `.load` content, and one stating program-mode stdin follows file-execution attribute handling (naming what that is).

**11. Percent-encoded separator handling is ambiguous. — Minor/Non-blocking**
Evidence: §3 "encoded separators and dot segments receive no exemption" can be read as decode-then-normalize or as refuse; Node refuses `%2F` in file URLs (`ERR_INVALID_FILE_URL_PATH`). Identity-based containment makes either safe, but a security-relevant parser rule should not be ambiguous. Resolution criterion: state explicitly whether `%2F` is refused (Node-compatible) or decoded and normalized.

**12. Assorted under-specification. — Minor/Non-blocking**
(a) Mode determination consults stdin only; behavior of banner/prompt with TTY stdin and piped stdout, and which stream the editor requires to be a TTY, is unstated. (b) The history digest input (which bytes, what domain separation) is unspecified (§12). (c) `NO_COLOR` set-but-empty is unresolved against the informal standard (§14). (d) SIGTERM (and SIGHUP) exit codes are unspecified against "the REPL introduces no exit code of its own." (e) "`.load foo.js` and `import './foo.js'` never disagree" overclaims — they agree on grammar but differ on goal (`export` legality, strictness). (f) §7 "drains the microtasks and ready native completions *needed for settlement*" implies infeasible selective scheduling; say "continues to drive ready work until the unit settles." (g) §8's "documented result of the submitted form" for import display is vague — state that import declarations are empty completions and only dynamic `import()` displays a value. Resolution criterion: a sentence each.

1. **`require.main` is promised by §3 and kept closed by §1 and the registry — Material.** §3 requires program mode to present "`require.main` naming it"; §1 says `require.main` (with `require.cache`, `process.mainModule`) is a closed `runtime:inspect` surface and resolves only the renderer and cache questions. 2. **The `Ibex.permissions`/`Ibex.authority` closure has no mechanism owner and ambiguous scope — Material.** §6 closes them "from root prompt code"; AC7 says "unreachable from the prompt". Does the session manifest project empty ceilings for the root row, or does the bridge gate on execution mode? These differ observably (does the API exist? throw? deny?). (b) scope — LLP 0021 WP8 lets a *package*-attributed `requestTyped` name itself within its own ceiling; if the REPL closes the surface session-wide, packages imported at the prompt behave differently than in file execution, contradicting §6's own "same typed decisions" and §7 parity. *Resolution:* specify the closure mechanism (recommended: the session manifest projects empty root escalation ceilings, stated in §2, plus an execution-mode fact on the bridge), state whether package-attributed dynamic requests are also closed, and add the distinguishing fixture to AC7.
