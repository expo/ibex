## Deferred `Reflect.construct` primitive prototype

This is a real 2020 miss, correctly left failing, and I do not treat it as fixed.

Pinned Hermes `JSCallableProxy::_proxyNativeCall` Gets `newTarget.prototype` before any construct trap. Ordinary JS functions (and public JSI host functions) then use GetPrototypeFromConstructor with **`%Object.prototype%`** as the intrinsic fallback. Built-in Intl constructors pass `%DateTimeFormat.prototype%` / `%NumberFormat.prototype%` instead.

Checked alternatives that are actually available here:

| Approach | Why it is not clean |
|---|---|
| Second `newTarget.prototype` Get in the JS constructor or a Proxy `construct` trap | Observable extra Get (accessors/proxies); test already pins one Get (`prototype,locale`) |
| If `Object.getPrototypeOf(this) === Object.prototype`, swap to the Intl prototype | Breaks explicit `newTarget.prototype = Object.prototype`, which the contract says must remain valid |
| Descriptor / `Object.prototype` heuristics | Extra proxy traps or the same conflation |
| Return a `jsi::HostObject` instance | Wrong prototype for custom object `newTarget`s |
| Engine built-in `[[Construct]]` or a private VM constructor seam | Hermes fork / non-public JSI; out of scope |

No demonstrably available clean alternative without an engine fork, a second observable Get, or a heuristic that mis-handles explicit `Object.prototype`. The two `#[ignore]` tests are the right record. Ordinary `new`, call-as-function, subclasses, and custom **object** prototypes are implemented.

## What held up

- **One native formatter.** `format` / `formatToParts` / Date locale methods all go through the same Rust-owned ICU formatter. No reconstruction from `resolvedOptions`, no output parsing.
- **Option order and Date locale methods.** Constructor: CanonicalizeLocaleList, then ToDateTimeOptions (`any`/`date`), then the 2020+dateStyle/timeStyle Gets, with timeZone validated before later component Gets. `Date.prototype.toLocale*` brands via `getTime` first, returns `"Invalid Date"` without observing locales/options, then the extra ToDateTimeOptions pass before construction.
- **Brand / bound `format`.** Brand before date coercion; bound function captures the opaque owner (not a JS-visible handle); WeakMap + `Weak<RuntimeState>` does not create a strong JS/native cycle. Prototype Get is only the engine’s one Get.
- **`nu` parser.** Stops at private-use `x`, consumes the full `nu` type (`arab-foobar` stays `arab-foobar`, not a supported `arab` prefix). Unsupported explicit types do not become supported prefixes. Numbering **option** comparison remains case-sensitive, as pinned (`ARAB` → `latn`).
- **SQLite admission.** Snapshot is taken in `Adapter` at runtime construction, before trusted Intl bytecode. Exactly four already-captured data properties are updated (`Number`/`BigInt` `toLocaleString`, String locale case). Unknown object/property and post-validation calls throw. Later replacement of an admitted method still fails the identity check. `Date` is not in the captured set, so Date locale replacement does not need admission. Hook order is NF + case + DTF, then accept, then fetch/sqlite factories, then harden.
- **Ownership / ABI.** Opaque JSI NativeState, checked UTF-8 spans, ICU `protect`/`noexcept`, result Guard, Mac-gated compile of the datetime TU, ops 130–137 handled before grant-bearing `Op`. Case mapping still uses explicit UTF-16LE for the mapped string (embedded NUL / lone surrogates); locale selection is still first requested locale.
- **Surface.** Factory is an evaluation completion, not a global; harden walks `Intl.DateTimeFormat` and Date locale methods from the global graph.
