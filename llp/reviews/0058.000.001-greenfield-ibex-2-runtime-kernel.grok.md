## Findings

### C1 — Bootstrap sequence contradicts the protocol critical section
**Where:** Target §6 steps 4–8; target §1 (0058.000.000 remains normative and is not superseded); capsule `llp/0058.000.000` §6.1–6.3.
**Failure mode:** This Spec owns work sequencing and gives a numbered production bootstrap. It installs construction-private adapters (step 4), then constructs operation bindings and immutable namespaces (step 5), and only then deletes construction roots and runs 0058.000.000 §6.1 lockdown (step 6). The protocol order is the opposite: capture/delete construction-private roots, freeze the intrinsic/global graph, *then* create and cache module bindings. Protocol §6.1 also forbids Promise jobs, getters, proxy traps, and embedder callbacks between adapter install and freeze.

Following §6 literally leaves `__ibex2ReadFile`-class roots and an unfrozen intrinsic graph live while host functions and namespace objects are created. Those objects may miss the receipt-bound freeze inventory, and GrantFree surfaces such as `TextEncoder` (vertical slice item 1, “shared”) have no specified install point relative to D8. Implementers cannot satisfy both sequences. Step 6’s “execute §6.1” does not repair this; it restates the whole protocol algorithm after the conflicting steps have already run.
**Class:** MATERIAL
**Disposition:** Make §6 a wrapper around 0058.000.000 §6.1, not a reordering of it: authenticate receipts → allocate kernel/runtime → capture pristine intrinsics → install, capture, and *delete* construction-private adapters → freeze/verify the root inventory while no jobs run → *then* mint contexts, cache namespaces, install receipt-bound GrantFree shared surfaces → invoke `FactoryV1` → enter the outer driver from `Idle`.

## Implementer reconstruction

### 1. Runtime construction and ownership

A greenfield instance is a single composition root that selects one receipt class, one posture, one authenticated policy/graph, one kernel, one public-Hermes adapter, and one set of platform services, then allocates a runtime. Family choice is an artifact choice: a secure greenfield binary has no patched family to select. Selection is immutable for the instance lifetime. Before a **secure** selection, the root authenticates the graduation-manifest digest (§3.5, §5, §6, §10).

The **kernel** owns every LLP 0058.000.000 record and transition, policy generation, authority mint/derive, resource-stage commit, host-task admit/commit, and teardown start. It also owns the owner-thread coordinator that **is** the §8 driver (`Idle` … `Closing`) and the §9 teardown machine. The kernel has no JSI, Hermes value, engine root, C++ runtime pointer, or transport. Adapter/services call the kernel only through the §4 operation contract. The coordinator calls them only through a JS-free hooks trait named `checkpoint`, `invoke`, `release`, `dispose`. Neither adapter nor services may run a pump or lifecycle machine. Engine roots and transport objects live in adapter- or service-owned slots keyed by the kernel. Slot mutation is supposed to occur only through coordinator `reserve → commit/rollback` acknowledgement. After `Closing`, no task may commit; no record may be recycled before the slot owner acknowledges release (§3, §3.1).

**Teardown barrier (fixed order):** coordinator enters `Closing` → services dispose/detach every slot and acknowledge → adapter releases every engine root and acknowledges → adapter destroys Hermes → kernel closes and recycles records (§3.1).

The **adapter** owns public Hermes create/destroy, `FactoryV1` and immutable namespaces, typed conversion, private-token closures/host objects, keyed root slots, refusal materialization, and coordinator-directed checkpoint/invoke/release. It must not use private VM headers, patched exports, frame/job identity, principal manufacture, a task queue or callback map, or legacy `ex_hermes_*` installers (§3.2).

**Platform services** own transport only, behind typed traits: no JS/engine values, no scalar that independently claims authority, verified facts for the next stage, `Staged` is not allow, kernel-keyed slots, producer-safe `CompletionLease` (§3.4). Process-global `Host`, `host::abi` maps, and the VFS generation registry are not eligible pools (§4.2, §9).

**Bootstrap** wraps 0058.000.000 §6.1 without claimed reordering (§6): authenticate `upstream-pinned` engine receipt **and** the greenfield build receipt → allocate Hermes and the kernel generation with coordinator `Idle` and job execution disabled → capture public intrinsics → install construction-private adapters and inventoried `GrantFree` shared surfaces, capture, delete, verify → freeze the receipt-bound inventory with no jobs → mint contexts/bindings/namespaces → verify inventory and quiescence → verify and invoke receipt-bound `FactoryV1` → enable jobs and enter the driver from `Idle`. Steps 3–7 are the no-project-code/no-job critical section. Any failure destroys the runtime; it does not select compatibility, insecure, patched, or legacy.

**First project entry** is a receipt-bound `FactoryV1`. The runtime loader verifies that receipt and must not transpile, rewrite globals, retrofit old HBC, discover modules ambiently, or fall back to a root context (§2.3, §3.3, §6).

### 2. Artifact and provenance

**Public-Hermes input.** Production Hermes is an exact upstream pin with a new G0 schema `ibex/hermes-upstream-pinned-receipt/1` and an independent validator. Patched/Maven classes cannot be relabeled. Android additionally requires a source-built empty-patch artifact. Checked-in authorities reconstruct: upstream tree, canonical empty patch manifest, build/lowering authorities, exact `hermesc` digest/flags, HBC ABI, target/variant, runtime/link artifacts, and final source/link manifests. Until graduation the pin is oracle/experimental: it cannot run untrusted code, or it is disclosed and trip-wired under LLP 0039 (§5, G0).

**Negative isolation.** The greenfield native source list is only the new adapter plus audited platform leaves. Empty Ibex patch-set digest; `patches/hermes/` is not a build input. Crate/module-path checks reject legacy engine, host composition root, module loader, JSI, C++ bridge, `crates/stdlib::boundary`, `stdlib_ffi`, `stdlib_adapter`, and `crate::host`. Header/link scans reject private/patched Hermes symbols, `currentPrincipalId`, principal-stack collectors, thread-local/root fallbacks, legacy authority globals, and scalar authority dispatch. The closed-world inventory starts from the artifact’s **actual** final source/link/entry-root manifests; any legacy object/export/bridge in the linked artifact fails the build (§5).

**Module receipt.** The builder authenticates the graph, lowers every supported shape to `FactoryV1`, optionally emits HBC, and binds code digest, format version, binding profile, stdlib surface, graph identity, and the `upstream-pinned` receipt’s `hermesc`/lowering/HBC-ABI identity. The loader instantiates only prepared factories that verify that receipt (§3.3). Direct-eval, authority-global HBC, and unbound ESM refuse before project code (via 0058.000.000 §6.2).

**Final artifact boundary.** Greenfield and patched are separate final artifacts. A secure greenfield artifact links exactly the greenfield closure. A product may ship both and load one before runtime creation. The secure profile has no dual-family executable. A dual-family binary needs a separate accepted amendment (family-tagged handle, authenticated dispatch, per-constructor reachability inventory). Sublibrary scans never authorize it (§5, §9).

**Graduation manifest.** Schema `ibex/greenfield-graduation-manifest/1`. Its digest is bound by “the §5 receipt” and by the composition root. It declares the application/API tier and enumerates required 0059.000 APIs with G4 classification (including permitted `Absent`), admitted module formats/graphs, application corpus from shipped HBC on every declared target, postures/triples/feature sets, final source/link closures, negative scans, the 0058.000.000 suite on both Hermes and mock adapters, closed-world inventory dispositions, adversarial/lifecycle fixtures, VFS/network stage evidence, receipt-mismatch refusals, negative packaging (oracle/incomplete receipts cannot enter a secure product), and LLP 0021 advertisement/conformance reports under the §1 amendment (§10).

**Product selection.** After the root authenticates that exact manifest digest, a consumer selects the **whole** greenfield artifact before allocation. No per-operation cutover inside a legacy runtime. Making greenfield the default is a later product decision (§8 G6, §10).

**Tier monotonicity.** A manifest may add entries. Dropping a required API, format, corpus member, target, or posture is a different tier that re-enters G6. Every **listed** entry must pass, not every implemented entry. Performance numbers are not security proof and cannot waive refusal/provenance/inventory/lifecycle gates (§10).

## Findings (priority order)

### GFK-M1 — Receipt cardinality and graduation digest are not one constructible object
**Classification:** MATERIAL  
**Target:** §5 “Receipt”; §6 step 1; §3.5; §10 first paragraph  
**Failure mode:** Two implementers cannot authenticate the same inputs.

§6 step 1 requires two receipts (“`upstream-pinned` engine receipt **and** the greenfield build receipt (§5)”). §5 names only `ibex/hermes-upstream-pinned-receipt/1`. §10 says the graduation-manifest digest is bound by “the §5 receipt” (singular) **and** the composition root. The reconstruction list in §5 never includes that digest.

Independent implementations will diverge on all of:

- whether graduation is a field of the Hermes pin receipt, a second unnamed build-receipt schema, or the graduation file itself;
- whether engine identity changes when APIs land (if the pin receipt must bind graduation);
- how many digests the composition root must check at secure selection (one, two, or three);
- whether “final source/link manifests” in the Hermes-named receipt are Hermes libs or the whole greenfield link closure, and whether they must equal the graduation manifest’s closures.

That is a fail-open provenance seam: an oracle pin, a kernel/link closure, and a graduation document can be mixed without a specified cross-digest. LLP 0021’s fail-closed mismatch cannot be implemented until the bound set is exact.

**Smallest sound disposition:** Name every receipt schema, list exact bound members, and state mandatory equalities. Minimally: (1) `ibex/hermes-upstream-pinned-receipt/1` binds only engine/source/empty-patch/`hermesc`/HBC-ABI/runtime-link identity; (2) a named greenfield **artifact** receipt binds final source/link/entry-root manifests, negative-scan results, and the graduation-manifest digest; (3) the composition root authenticates both plus the graduation document; (4) graduation’s source/link closures MUST equal the artifact receipt’s. G0 may ship (1) with (2) marked oracle/unbound; G6 refuses a secure product if (2) is unbound or unequal.

### GFK-M2 — Who commits a host task, and what an “acknowledgement” is, contradicts the delegated driver
**Classification:** MATERIAL  
**Target:** §3.1 (kernel-only commit; `reserve → commit/rollback` acknowledgement; hooks trait); §8 G1; delegated 0058.000.000 §8 step 3  
**Failure mode:** Two pumps, lost work, or commits after `Closing`.

0058.000.000 §8 step 3 says the **adapter** revalidates, **commits** one source transition, and invokes. This Spec says **only the kernel** may admit or commit a host task, the coordinator **is** the driver, and the adapter implements hooks and must not own a task queue. It never maps §8 onto those hooks: who revalidates engine roots vs kernel records, what the ack payload is, whether commit precedes `invoke` or follows it, and what a failed `invoke` does to the FIFO.

Two competent implementers will ship different linearizations for the races §7.5 and 0058.000.000 §7 already freeze (queue admission failure, nested drive, duplicate/late completion, `Closing` vs delivery). That is a protocol-coherence defect this Spec created by moving the driver into the kernel without rewriting the commit actor.

**Smallest sound disposition:** Normative mapping, owned here: coordinator calls `checkpoint`; kernel **reserves**; kernel revalidates records; adapter hook revalidates/releases only engine slot state; kernel **commits** (the sole commit); coordinator calls `invoke`; failure is rollback-to-same-position or one terminal dispose; then `checkpoint`. Acknowledgements are synchronous owner-thread returns. No second FIFO.

### GFK-M3 — Runtime loader is required but not in the normative topology
**Classification:** MATERIAL  
**Target:** §3 topology diagram (“dependency graph and ownership below are normative”); §3.2; §3.3; §6 steps 6 and 8; §3.5  
**Failure mode:** Adapter-minted principals, or two FactoryV1 paths.

§3.3 requires a runtime loader that authenticates the graph and instantiates `FactoryV1`. The loader is absent from the §3 graph (builder is build-time only; runtime boxes are kernel, adapter, services, composition root). §3.2 also says the adapter owns “`FactoryV1` and immutable namespaces.” §6 step 6 mints contexts “through the captured native state”; step 8 “verify and invoke only a receipt-bound `FactoryV1`” has no caller.

0058.000.000 forbids the **engine** from supplying a principal (`mint_context` is loader → kernel). If implementer A puts the loader inside the adapter, the adapter becomes the principal supplier and can violate §3.2. If implementer B puts it in the kernel, the kernel gains graph/policy I/O this Spec said it does not have. If implementer C has both adapter and loader invoke factories, bootstrap and import can disagree.

**Smallest sound disposition:** Add the runtime loader as a fourth runtime component in §3, owned by the composition root or a kernel-adjacent crate that is **not** the Hermes adapter. Only the loader calls `mint_context` and asks the adapter to invoke `FactoryV1` with a kernel-issued namespace token. The adapter never learns a `PrincipalId`.

### GFK-M4 — Teardown acknowledgement failure can skip the barrier
**Classification:** MATERIAL  
**Target:** §3.1 barrier and “cannot reorder”; hooks list includes `dispose` but §3.2 adapter omits it  
**Failure mode:** Recycle/destroy while transport or engine roots still live.

The barrier order is stated, but not: ack is synchronous and mandatory; a failed or missing ack MUST NOT start the next step; records MUST NOT recycle; whether failure terminates, leaks, or hangs. Combined with one shared hooks trait (`dispose` on adapter **and** services), the coordinator may call adapter `dispose` first and destroy Hermes before services detach, which is exactly the reorder §3.1 forbids.

Current stdlib FFI retains extra `Arc`s on async workers and expects C++ to `runtime_free` after drain (`ibex2_stdlib_read_file_async` / `ibex2_stdlib_runtime_free`). A greenfield implementer copying that pattern without a fail-closed barrier will settle or free across `Closing`.

**Smallest sound disposition:** Split hooks: services `{dispose}`; adapter `{checkpoint, invoke, release, destroy_engine}`. Each barrier step is a synchronous owner-thread ack. Failure: do not recycle; do not proceed; late `CompletionLease` results drop without JS; engine destroy runs only after successful adapter `release`. Hang vs process-fatal on a stuck transport is an explicit choice; silent skip is not.

### GFK-M5 — Module receipt copies `hermesc`/HBC-ABI identity but need not equal the live engine receipt
**Classification:** MATERIAL  
**Target:** §3.3; §5 receipt reconstruction; §6 steps 1 and 8  
**Failure mode:** Prepared HBC from pin A executes on pin B; ABI/safety and provenance both break.

The builder binds the **pin receipt’s** `hermesc`/lowering/HBC-ABI identity into the module receipt. The loader “verifies that receipt.” Nothing requires equality with the runtime’s authenticated `upstream-pinned` receipt before `FactoryV1` invocation. Two implementers will ship (A) module-local digest/format checks only, vs (B) exact cross-bind to the loaded engine.

This Spec owns construction isolation and is the document that added `hermesc` to the module receipt; 0058.000.000’s FactoryV1 fields do not cover this cross-check.

**Smallest sound disposition:** Loader MUST refuse unless module receipt `hermesc` digest/flags, lowering authority, and HBC ABI equal the already-authenticated engine receipt. Mismatch is a startup refusal, not a warning.

## Coherence and feasibility notes (not separate defects)

- **Ownership cycle at types, not crates.** Kernel-defined hooks + adapter calling §4 operations is acyclic if the kernel crate does not depend on the adapter. §5 mechanically bans legacy deps, not kernel→adapter. Remaining choice §12.2 is enough **if** GFK-M2/M3/M4 are closed; otherwise “mechanically enforced ownership” has nothing precise to enforce.
- **Bootstrap is satisfiable** once kernel generation exists before any host function is installed and job execution stays disabled until §6 step 9. G0 is the right kill switch if stock Hermes cannot create a runtime without running jobs.
