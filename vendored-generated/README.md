# Vendored generated artifacts (LLP 0180 §1.4 option a)

These files are **pre-generated** in the `exact` monorepo and committed here so the
standalone Ibex repo (`exact-runtime` crate at the repo root) can build without the
monorepo present.

`build.rs` detects the standalone layout (the monorepo generator scripts under
`packages/exact-devtools/src/scripts/` are absent) and, instead of running those
generators or panicking, copies these vendored artifacts into `OUT_DIR` so the
existing `include!` / `#include` consumers work unchanged. When the monorepo IS
present (exact's own build), build.rs regenerates everything as before — the
vendored copies are ignored.

## Contents

- `builtin_manifest.generated.rs`
  Consumed by `src/module_loader/mod.rs` via
  `include!(concat!(env!("OUT_DIR"), "/builtin_manifest.generated.rs"))`.
  Generated by `packages/exact-devtools/src/scripts/generate-module-manifest.ts`.
  The 8 `generated_builtin_source` arms that originally `include_str!`'d monorepo
  paths have been repointed to `OUT_DIR/builtins/*` (see below).

- `builtins/*.js`
  47 transformed builtin modules (the output of `build-builtins.mjs`, copied from
  the monorepo `OUT_DIR/builtins/`) **plus** 8 modules copied from monorepo source
  trees that the manifest references directly:
    - `exact-http-server.js`            <- packages/exact-runtime-js/src/http-server/index.js
    - `exact-sqlite.js`                 <- packages/exact-runtime-js/src/sqlite/module.js
    - `harness-bun.js`                  <- test/compat/harness/bun.js
    - `harness-bun-adapter.js`          <- test/compat/harness/bun-adapter.js
    - `harness-harness.js`              <- test/compat/harness/harness.js
    - `harness-node-harness.js`         <- test/compat/harness/node-harness.js
    - `harness-bun-jsc.js`              <- test/compat/harness/bun-jsc.js
    - `harness-bun-internal-for-testing.js` <- test/compat/harness/bun-internal-for-testing.js
  build.rs copies this whole dir into `OUT_DIR/builtins/` standalone.

- `embedded_runtime_bundle.js`
  The bundled shared runtime (output of `rolldown-bundle.mjs` from
  `packages/exact-runtime-js/src/runtime-entry.ts`). build.rs wraps it into
  `OUT_DIR/runtime_bundle_source.h` (C++ raw-string literal) and compiles it to
  `OUT_DIR/runtime_bundle_bytecode.h` via the present `hermesc`.

## NOT vendored (regenerated at build time from sources already in this repo)

- `bootstrap_source.h` / `bootstrap_bytecode.h` and the per-file `*.hbc`
  Generated from `src/engine/bootstrap/*.js` (present in this repo) using the
  bundled `tools/hermes/hermesc-linux-x64`.
- `runtime_bundle_bytecode.h`
  Compiled from `embedded_runtime_bundle.js` via `hermesc`.
- `*.o`, `*.a` (Hermes/Brotli object and archive files) — platform build products.

## Regenerating

Build `exact-runtime` inside the monorepo, then copy from its `OUT_DIR`:
`builtin_manifest.generated.rs`, `builtins/*.js`, `embedded_runtime_bundle.js`.
Re-apply the OUT_DIR repointing in the manifest's `generated_builtin_source` and
re-copy the 8 monorepo source files listed above.
