### Material findings

1. **High — explicit calendar options are incorrectly case-folded.**  
   [`intl_datetime.rs:328`](/Users/ccheever/release-inputs/snapback2-intl-20260911/r2/candidate/crates/ibex2/src/stdlib/intl_datetime.rs:328)

   Under the selected ECMA-402 2020 contract, explicit Unicode-type options are compared exactly against locale data. The candidate lowercases `calendar`, unlike the corrected `numberingSystem` path.

   Reproduction:

   ```js
   new Intl.DateTimeFormat("en-US", {
     calendar: "BUDDHIST", timeZone: "UTC", year: "numeric"
   }).resolvedOptions().calendar
   ```

   The candidate selects `"buddhist"` and changes formatted years; `"BUDDHIST"` should be an unsupported well-formed option and leave the default `"gregory"` selected.

   Minimal correction: retain the original calendar string instead of applying `to_ascii_lowercase`, and correct the focused uppercase-calendar assertion.

2. **High — DateTimeFormat’s retained Unicode extension is computed from raw option presence, not ResolveLocale’s effective override.**  
   [`intl_datetime.rs:392`](/Users/ccheever/release-inputs/snapback2-intl-20260911/r2/candidate/crates/ibex2/src/stdlib/intl_datetime.rs:392), [`intl_datetime.rs:694`](/Users/ccheever/release-inputs/snapback2-intl-20260911/r2/candidate/crates/ibex2/src/stdlib/intl_datetime.rs:694)

   Two reproducible inconsistencies result:

   ```js
   new Intl.DateTimeFormat("en-US-u-ca-buddhist", {
     calendar: "foobar", timeZone: "UTC", year: "numeric"
   }).resolvedOptions()
   ```

   The supported `ca-buddhist` extension still selects Buddhist formatting, but the candidate removes it from `locale`. An unsupported explicit option must not clear a supported requested extension.

   ```js
   new Intl.DateTimeFormat("en-US-u-hc-h23", {
     hour12: true, timeZone: "UTC", hour: "numeric"
   }).resolvedOptions()
   ```

   The candidate can report `locale: "en-US-u-hc-h23"` together with `hourCycle: "h12"`. Supplying `hour12` sets the `hc` ResolveLocale option to null and must remove the overridden `hc` extension.

   Minimal correction: track whether each explicit option was actually supported and cleared the extension; unsupported `ca`/`nu` options retain the extension, while any supplied `hour12` suppresses retained `hc`.

3. **Medium — time-zone matching uses Unicode folding instead of ASCII-insensitive matching.**  
   [`intl_datetime_icu.cc:269`](/Users/ccheever/release-inputs/snapback2-intl-20260911/r2/candidate/crates/ibex2/src/engine/intl_datetime_icu.cc:269)

   `u_strCaseCompare` folds non-ASCII characters. For example, `"Asia/Kolkata"` uses Kelvin sign U+212A, which folds to ASCII `k`, so it can match ICU’s `"Asia/Kolkata"` and be accepted. ECMA-402’s comparison is ASCII-case-insensitive; this input must throw `RangeError`.

   Minimal correction: require explicit identifiers to be ASCII before inventory matching, then compare with ASCII-only case folding.
