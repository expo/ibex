## Async fetch (LLP 0068.000)

`FetchTask` in `crates/ibex2/src/stdlib/fetch_async.rs` reuses `admit_hop`, `redirect_step`, and `prepare_body` from `fetch.rs`. Per-hop grant checks run before `hop` is incremented (lines 365–369). Header caps and declared-length ceilings apply on every hop, including redirects (HopSink `head`, 477–495). Body collection uses saturating length checks and fallible `try_reserve_exact` (521–531).

`Exchange::start` returns `Err` with no accepted exchange. `Ok` records the exchange, then activates outside the task lock (391–409). Pre-activation cancel sets the cancelled flag and still calls `activate()` so a prepared hop retires (165–176). `decide()` publishes one terminal outcome; later `end` only releases hop resources (432–445, 534–615). HopSink drops the strong `FetchTask` at physical end; late metrics keep observer + hop URL only (448–456, 618–620). Callback panics are contained (`contain`, `catch_unwind` on `next_hop`).

`BoundedWorkerPool` reserves during `start` (`WorkerService::reserve`, 707–718). `dispatch` cannot run inline; the permit drops when the worker begins the job so a one-slot service can prepare a redirect from `end` (638–641, 691–704). `BlockingAdapter` copies the upload for `Request::body` as the RFC records; `Upload`’s last-release callback tracks the shared original (721–725, 774). Cancel-before-activate still dispatches so `end` runs; `run_blocking` checks the signal before `transport.open` (770–776).

JSI `fetch` remains the existing blocking `fetch_stream` on the host pool (`boundary_abi.rs` 1167–1172). The new async surface is the Rust-consumer path.

## Native Apple session and upload stream

`DarwinLane` is a lazy reusable ephemeral `NSURLSession`: no cookies, no URL cache, native redirects completed with `nil` (`darwin_task.mm` 337–344, 307–313; `darwin_async.rs` 50–57). Callbacks run on the session’s serial queue. Invalid method/URL/header values become a queued `end`, not an inline sink call (`darwin_async.rs` 115–135, 389–391).

Upload owner: `Ibex2Upload` holds the Rust `Arc<Upload>` pointer; `Ibex2UploadStream` copies at most 64 KiB under the same lock as `detach`; `getBuffer` returns `NO` (109–124). `needNewBodyStream` mints a new stream from the same owner for replay (302–306). Physical completion detaches before `ibex2_async_end` and frees the sink there, so late Foundation metrics cannot keep upload bytes or consumer closures (`endWith` 263–278). Empty bodies use `dataTask`; nonempty bodies use `uploadTaskWithStreamedRequest` (435–436). Lane destroy invalidates and retires unactivated delegates (369–386).

Cancel-before-activate sets `cancelled` and relies on `Exchange::cancel` → `activate` to retire without `resume` (474–481, 456–469). A cancel that wins after `start.activated` is set, then a queued `resume`, is a no-op on a cancelled `NSURLSessionTask`; the hop still gets one `didCompleteWithError`.

## Storage, retained handles, limits

`doc:/` parsing rejects `\`, NUL, `//`, `.`, and `..` (`documents.rs` 140–158; `grant.rs` 70–75). Prefix matching is by whole components: `doc:/1` does not admit `doc:/10` (`grant.rs` 98–108). Every `run_document` admits `fs.read`/`fs.write` before the provider (167–189). File leases require `parts.len() == 2` and `parts[1] == leaf`, and refuse Remove/Mkdir/ReadDir (206–215). Directory leases refuse removing the selection itself (`parts.len() <= 2` or empty relative, 220–222). Rename/copy/realpath are unsupported (176–178). Guest errors use kind + logical path only (`DocumentError::guest`, 36–50).

Unix/Windows document ops walk retained parent FDs/handles with `O_NOFOLLOW` / `FILE_OPEN_REPARSE_POINT` + reparse refusal (`app_fs_unix.rs` 37–44, 541–567, 570–680; `windows_directory.rs` 69–76, 127–137). Metadata and bytes for a document read share the opened object (`document_read` 160–169; Unix ReadFile 617–620). Envelope reads go through `read_bounded_file` with a one-byte probe past the cap (`fs.rs` 68–110). Directory names are charged at encoded size (`push_name`, 123–139). Recursive native/app removal uses 256-entry batches independent of the listing budget (Unix `batch_names`/`require_progress` 178–222; Windows `names_batch` 310–375).

`Host::read_bounded` is the grant-checked app-directory reader with a caller cancel hook (`host.rs` 544–555). Image source reads use that path with `WorkControl::check` (`fs_image.rs` 494–498).

## Image cancellation versus commit (LLP 0068.001 §5)

States Queued → Running → CommitStarted → Settled / Abandoned are ordered on one per-work lock (`fs_image.rs` 149–233). `ImageJob::prepare` admits both grants, requires `app:/`, checks codec/service limits, then `ImageWork::admit` (418–466). Missing codec fails before source I/O. Destination parent is pinned before the codec (492–493). `reserve_commit` is the only Running → CommitStarted transition and fails closed on Abandoned or expired trial budget (212–223). The observer and `target.write` run after that lock is released (518–523). Confirmed Abandoned cannot publish; a losing cancel returns `CommitStarted` immediately and later observes the real write (`losing_cancel_is_immediate_and_preserves_real_publication_outcome`, 784–812). Panic in codec or observer settles and releases the worker (663–685). Default limits: 4 workers, 16 completions, 256 MiB job, 64 MiB source/output, 20 s trial, 4 KiB diagnostic cap.

JSI opcode 121 is `fs.compressImage` (`host_opcodes.rs` 157; `install.cc` 2073). Work is registered on the owner thread before `pool::run` (`boundary_abi.rs` 921–955). Prepare failure completes through the existing FIFO after the Promise executor has stored resolve/reject (`install.cc` 1996–2011). TypeScript and the ABI take four arguments; there is no guest `AbortSignal`. Teardown calls `image_work().close()` then drops `image_tasks` (`task.rs` 977–981). After `Abandoned`, destination bytes stay the old target (`tracked_storage.rs` 104–117).

`ImageOwner` closes engine-free work when the last `Bindings` clone drops (`host.rs` 497–501). `with_runtime_configuration` keeps the source `ImageWork` on the snapshot; owning Hermes uses `RuntimeState`’s own `OnceLock` (`task.rs` 668–676, 839–884). The owning-runtime test shows source workers stay 0 after adopt and after dropping the source Context (`tracked_storage.rs` 200–208).

## Host / Context / JSI integration

Both doors share `run_with_limits` → `run_with_documents` (`fs.rs` 600–652; Host `Fs::run` 505–521; JSI `run_fs` 1226–1278). `ibex2_bindings_adopt` snapshots Context directories, sqlite, documents, image service, and storage limits, then `adopt_bindings` copies any still-empty owner OnceLocks (`bindings.rs` 675–697; `task.rs` 855–884). Provider/codec callbacks are outside registry and completion-queue locks.

JSI host pool remains capped at 64 (+ 4 body workers) (`pool.rs` 29–32). Image admission is a separate 4/16 budget on `ImageWork`, so compressImage cannot grow threads past that work registry.
