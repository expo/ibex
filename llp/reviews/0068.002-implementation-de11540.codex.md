# Consumer adoption implementation review — worker lifetime follow-up

- Date: 2026-10-13
- Reviewer: `gpt-5.6-sol`, reasoning `xhigh`, independent collaboration review
- Reviewed: `30b0db0..de11540`
- Scope: source only; no edits, builds, delegation or remote commands
- Verdict: **no material findings for `de11540`.**

The consumer review found that retaining an entire worker budget in dispatched
jobs does not cover idle thread retirement: dropping a pool closes its sender,
but detached worker threads may still be leaving the receive loop when a
replacement consumer claims the returned capacity.

The upstream response adds `BoundedWorkerPool::with_worker_guards`. Each
successful thread owns its guard through idle wait, accepted-job draining,
panic containment and receive-loop exit. If spawning fails partway through,
the failed closure and remaining iterator release only unstarted guards;
started threads retain their guards. Destruction introduces no blocking join.

The reviewer inspected both lifetime witnesses and confirmed that this API is
sufficient for Exact to transfer its individual process-wide worker slots.
The consumer implementation of that transfer receives its own review.
