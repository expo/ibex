# `ibex run` refuses with "legacy v1 target advertisements are diagnostic-only" for a plain script consumer

**Status:** Closed
**Resolution:** intentional refusal documented; production enablement remains tracked elsewhere
**Date:** 2026-08-04
**Resolved:** 2026-08-04
**Reporter:** Weird Castle dogfooding (multiplayer sim-core differential gate; Claude on behalf of Charlie)
**Binary:** `target/release/ibex` built 2026-08-03
**Related:** `issues/20260717-sfe-capsec-advertisement.md`; `issues/20260728-capsec-public-surface-evidence-backlog.md`; `issues/closed/20260804-sandbox-runtime-cache-root.md`

## What happened

Weird Castle invoked:

```
ibex --history off --project-root <server-dir> run <generated>.mjs
```

and production arming refused because the checked target advertisement catalog
is still schema v1. That refusal is intentional: v1 is the closed compatibility
state, while a v2 row must be generated by the standard conformance and
promotion pipeline. A project path cannot safely mint its own target evidence.

## Resolution

- The CLI refusal now explains that `--project-root` only selects the mounted
  project, identifies the production-advertisement dependency, and labels
  `ibex capsec audit <file>` as an unarmed diagnostic workflow.
- The README documents the same source-run posture.
- Production enablement remains owned by
  `issues/20260717-sfe-capsec-advertisement.md` and its public-surface evidence
  dependency. This ticket does not duplicate that live work.
- The independent sandbox cache failure was split into
  `issues/closed/20260804-sandbox-runtime-cache-root.md` and fixed separately.

No guard was weakened, and `--project-root` does not generate advertisements.
